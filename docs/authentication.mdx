---
title: "Authentication"
description: "Authenticate server-to-server requests with an organization API key."
---

Every `/api/v1` request requires an API key generated by an organization trainer (an admin or team member) on the [Developer API page](https://dash.trainertwin.com/developer).

## Send the key

Use the `x-api-key` header for every request.

```bash
curl "https://dash.trainertwin.com/api/v1/sessions" \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

TrainerTwin also accepts a bearer token for platforms that cannot configure a custom header.

```bash
curl "https://dash.trainertwin.com/api/v1/sessions" \
  --header "Authorization: Bearer $TRAINERTWIN_API_KEY"
```

<Note>
  Prefer `x-api-key`. Send only one authentication header per request.
</Note>

## Key behavior

| Property | Behavior |
| --- | --- |
| Ownership | One organization |
| Permissions | Read and write users (including learner credit grants) and assignments; read sessions and scenarios |
| Expiration | One year after generation |
| Rate limit | 120 requests per minute, per key |
| Storage | Hashed; the full key cannot be recovered |

The organization is derived from the key. Requests cannot supply or override an organization ID.

## Rotate a key

<Steps>
  <Step title="Generate a replacement">
    Create a new key on the [Developer API page](https://dash.trainertwin.com/developer).
  </Step>
  <Step title="Update your platform">
    Replace the stored secret and confirm a request succeeds with the new key.
  </Step>
  <Step title="Revoke the old key">
    Return to the [Developer API page](https://dash.trainertwin.com/developer) and revoke the previous key.
  </Step>
</Steps>

Revocation takes effect immediately.

## Authentication errors

```json
{
  "error": "Send a valid API key.",
  "code": "api_key_invalid"
}
```

- `401` — the key is missing, invalid, expired, or revoked.
- `429` — the key exceeded its rate limit.
- `403` — the key lacks a required scope (`scope_missing`), or its creator is no longer an enabled admin/team member (`api_key_owner_gone`).

Credit reads use `users:read`; grants use `users:write`. There is no new credits scope or required key rotation.

See [Errors](/errors) for the complete error model.
