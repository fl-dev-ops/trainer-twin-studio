---
title: "Authentication"
description: "Authenticate every request with one organization API key."
---

Every `/api/v1` request needs an API key created by an organization admin or team member on the [Developer API page](https://dash.trainertwin.com/developer).

The key belongs to one organization. The request cannot choose a different organization.

## Send the key

Prefer the `x-api-key` header.

```bash
curl "https://dash.trainertwin.com/api/v1/users" \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

A bearer token is accepted when a platform cannot set a custom header.

```bash
curl "https://dash.trainertwin.com/api/v1/users" \
  --header "Authorization: Bearer $TRAINERTWIN_API_KEY"
```

Send one of these, not both. If both are present, `x-api-key` is the one that is checked.

## What a key can do

| Permission | Allows |
| --- | --- |
| `scenarios:read` | List and read published role plays |
| `users:read` | List and read learners; read organization and learner credits |
| `users:write` | Add, rename, and disable learners; grant credits |
| `assignments:read` | List and read assignments |
| `assignments:write` | Assign, move, and remove assignments |
| `sessions:read` | List and read role-play sessions |

Credit routes do not have their own permission. A key that cannot read users cannot read credits either, and the error says `users`.

| Property | Value |
| --- | --- |
| Prefix | `tt_` |
| Lifetime | One year from creation |
| Rate limit | 120 requests per minute, per key |
| Storage | Hashed. The full secret is shown once and cannot be recovered. |

The API acts as the admin or team member who created the key. If that person is disabled or no longer on the team, every request returns `403` `api_key_owner_gone` until you create a new key.

## Replace a key

<Steps>
  <Step title="Create the replacement">
    Create a new key on the [Developer API page](https://dash.trainertwin.com/developer).
  </Step>
  <Step title="Switch your server">
    Store the new secret and confirm one read succeeds before revoking the old key.
  </Step>
  <Step title="Revoke the old key">
    Revoke it on the same page. Revocation is immediate.
  </Step>
</Steps>

Replacing the key does not erase credit-grant retry keys. Those belong to the organization, not to one API key.

## Authentication errors

```json
{
  "error": "Send a valid API key.",
  "code": "api_key_invalid"
}
```

| Status | Code | When |
| --- | --- | --- |
| `401` | `api_key_invalid` | Missing, unknown, expired, or revoked key |
| `403` | `scope_missing` | The key cannot perform that read or write. The message names the permission resource, such as `This API key can't read scenarios.` |
| `403` | `api_key_owner_gone` | `This API key's owner is no longer on the team. Create a new key.` |
| `429` | `rate_limited` | Over 120 requests per minute. Wait the seconds in `Retry-After`. |

See [Errors](/errors) for refusals that happen after the key is accepted.
