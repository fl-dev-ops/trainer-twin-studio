---
title: "Role plays"
description: "List the role plays published in your organization. The path is /scenarios."
---

A **role play** is the practice a learner can be assigned. This API can list and read published role plays. It cannot create, edit, archive, or publish them. Do that in the [TrainerTwin dashboard](https://dash.trainertwin.com) first.

The path is `/scenarios`, and the assignment field is `scenario`, because older integrations use those names. The value you store is the role play's `slug`.

Twins are not listed. An archived role play is not listed and returns `404`. A private role play is included when it belongs to this organization and is not archived. `visibility` describes the dashboard setting; it does not hide the role play from this API key.

Permission: `scenarios:read`.

## List role plays

```bash
curl "https://dash.trainertwin.com/api/v1/scenarios?limit=50" \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

`200`:

```json
{
  "scenarios": [
    {
      "slug": "react-mock-interview",
      "name": "React mock interview",
      "version": 3,
      "visibility": "public",
      "order": 0,
      "assignmentCount": 12,
      "createdAt": "2026-08-01T10:00:00.000Z",
      "updatedAt": "2026-08-30T14:20:00.000Z"
    }
  ],
  "pagination": { "limit": 50, "offset": 0, "total": 1 }
}
```

Order matches the dashboard: `order` ascending, then newest first. `assignmentCount` counts open assignments (`pending` and historical `used`). Cancelled and expired assignments are not counted. `version` increases when the role play is saved in the dashboard. A call keeps the version it started with; read that from the session, not from this list.

## Read one role play

```bash
curl "https://dash.trainertwin.com/api/v1/scenarios/react-mock-interview" \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

`200` adds `data`, the dashboard configuration. It can contain an objective, difficulty, and persona hints. Treat `data` as display content. Its fields can change and are not a stable contract for running the call.

```json
{
  "scenario": {
    "slug": "react-mock-interview",
    "name": "React mock interview",
    "version": 3,
    "visibility": "private",
    "order": 0,
    "assignmentCount": 12,
    "createdAt": "2026-08-01T10:00:00.000Z",
    "updatedAt": "2026-08-30T14:20:00.000Z",
    "data": {
      "objective": "Assess React fundamentals under interview pressure."
    }
  }
}
```

An unknown slug, a twin slug, or an archived role play is `404` `not_found`.

## Use the slug

Pass `slug` as `scenario` to [assign](/guides/assignments) it, and as the `scenario` filter when [listing sessions](/guides/sessions). On a session object the same value is `agentSlug`.
