---
title: "Assignments"
description: "Give a learner a personal link to one published role play."
---

An **assignment** connects one learner to one role play. The learner opens `practiceUrl`, signs in with the assigned email, and can practice again until the link is cancelled or their access is disabled. Each practice is a new [session](/guides/sessions) with the same `assignmentId`.

The role-play field is `scenario`. Its value is the `slug` from [Role plays](/guides/scenarios).

Permission: `assignments:read` to list or read, `assignments:write` to assign, move, or remove.

## Who can be assigned

Send `userId` or `email`, never both.

- `userId` must already be an enabled learner in this organization. A trainer or disabled learner is refused. An unknown ID is `404`.
- `email` adds a new learner first, with 30 starting credits, then assigns. If the organization cannot cover those 30, nothing is added and nothing is assigned.

Credits belong to the learner, not to the assignment. A second role play does not add another 30. See [Credits](/guides/credits).

## Assign

```bash
curl "https://dash.trainertwin.com/api/v1/assignments" \
  --request POST \
  --header "x-api-key: $TRAINERTWIN_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "userId": "user_123",
    "scenario": "react-mock-interview"
  }'
```

`201` when a link is created or a closed link is reopened:

```json
{
  "assignment": {
    "id": "assignment_123",
    "assignedAt": "2026-09-01T09:30:00.000Z",
    "userId": "user_123",
    "email": "avery@example.com",
    "scenario": "react-mock-interview"
  },
  "practiceUrl": "https://your-org.trainertwin.com/s/AbC123",
  "created": true,
  "emailSent": true
}
```

`200` when that learner already has an open assignment for that role play. `created` is false, `emailSent` is omitted, and the existing `practiceUrl` is returned. Send the same request again after a timeout; it will not create a second link or a second email.

A cancelled or expired assignment is reopened instead. That response is `201`, with a new `practiceUrl` and an email. The assignment ID stays the same, so earlier sessions remain attached to it.

`emailSent: false` does not undo the assignment. Show `practiceUrl` in your platform as well.

The email subject is `New role play: {name}`. It names the role play, the learner's credit balance, and the email they must use to sign in. A person added in this request is told they were added in that same email.

| Result | Status | Code |
| --- | --- | --- |
| Both `email` and `userId`, neither, or a slug that fails the pattern | 400 | `invalid_input` |
| Unknown, archived, or twin slug | 404 | `not_found` |
| `userId` is unknown in this organization | 404 | `not_found` |
| Disabled learner | 409 | `person_disabled` |
| Admin or team member | 409 | `person_is_studio` |
| Balance cannot cover a new learner's 30 credits | 409 | `minutes` |
| Organization plan is paused and a new grant is required | 403 | `minutes` |

The slug pattern is `^[a-zA-Z0-9][a-zA-Z0-9._-]*$`.

## Assignment detail

```bash
curl "https://dash.trainertwin.com/api/v1/assignments/assignment_123" \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

```json
{
  "assignment": {
    "id": "assignment_123",
    "assignedAt": "2026-09-01T09:30:00.000Z",
    "status": "pending",
    "practiceCount": 2,
    "lastPracticedAt": "2026-09-02T10:01:00.000Z",
    "user": {
      "id": "user_123",
      "name": "Avery Patel",
      "email": "avery@example.com"
    },
    "scenario": {
      "slug": "react-mock-interview",
      "name": "React mock interview",
      "version": 3,
      "visibility": "public"
    },
    "practiceUrl": "https://your-org.trainertwin.com/s/AbC123"
  }
}
```

| Field | Meaning |
| --- | --- |
| `status` | `pending` is open, whether or not they have practiced. `used` is an older open status and still works. `cancelled` is closed. `expired` remains only on links created before links stopped expiring. |
| `practiceCount` | Sessions started from this assignment, excluding failed starts. Do not infer this from `status`. |
| `lastPracticedAt` | When the latest counted practice started, or `null`. |
| `scenario.version` | Current published version, not necessarily the version used in an older session. |

List with `GET /assignments`. Filter by `userId` or `email`, never both, and optionally `scenario`. An invalid email, or both recipient filters, is `400`. A filter that matches nobody returns an empty page, including a disabled or foreign learner. Newest first.

Cancelled and expired rows remain readable. Removing the only unused link makes that ID `404`.

## Move

```bash
curl "https://dash.trainertwin.com/api/v1/assignments/assignment_123" \
  --request PATCH \
  --header "x-api-key: $TRAINERTWIN_API_KEY" \
  --header "content-type: application/json" \
  --data '{ "scenario": "system-design-interview" }'
```

Send at least one of `userId`, `email`, or `scenario`. Never send both `userId` and `email`. An empty body is `400`.

A real move cancels the old link and returns the destination. `changed` is true, `emailSent` is present, and `practiceUrl` is the destination link. The old URL stops working. Session history stays on the assignment that produced it.

If the destination learner and role play already have a closed assignment, that row is reopened and its ID is returned. If they already have an open one, the response is `409` `assignment_exists` and the source is left as it was.

Sending the destination again returns `200`, `changed: false`, the same `practiceUrl`, and no email. A closed source whose destination is not open returns `403` `roleplay_access_removed`.

Disabled and trainer recipients are refused even when the request would otherwise change nothing.

## Remove an unused assignment

```bash
curl "https://dash.trainertwin.com/api/v1/assignments/assignment_123" \
  --request DELETE \
  --header "x-api-key: $TRAINERTWIN_API_KEY"
```

`204` only when the assignment is `pending` and has no session rows at all. An unstarted, failed, or deleted session still counts, so that link cannot be removed here.

Every other state, and a second delete, is `404`. Nothing is refunded and no email is sent. To remove all of a learner's access, [disable the learner](/guides/users). To replace the role play, move the assignment.
