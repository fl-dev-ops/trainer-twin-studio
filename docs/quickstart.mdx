---
title: "Quickstart"
description: "Create an API key and make your first TrainerTwin request."
---

<Steps>
  <Step title="Generate an API key">
    Open the [Developer API page](https://dash.trainertwin.com/developer), enter a descriptive key name, and select **Generate key**.

    Copy the key immediately. TrainerTwin only displays the full value once.
  </Step>

  <Step title="Store the key on your server">
    Save the key in your platform's secret manager or server environment.

    ```bash
    TRAINERTWIN_API_KEY=tt_your_key
    ```

    <Warning>
      Do not put this value in frontend environment variables, source control, logs, or screenshots.
    </Warning>
  </Step>

  <Step title="List your learners">
    Send the key in the `x-api-key` header.

    ```bash
    curl "https://dash.trainertwin.com/api/v1/users" \
      --header "x-api-key: $TRAINERTWIN_API_KEY"
    ```

    A successful response returns your organization's learners and pagination metadata (`invitations` is always empty).

    ```json
    {
      "users": [],
      "invitations": [],
      "pagination": {
        "limit": 50,
        "offset": 0,
        "total": 0
      }
    }
    ```
  </Step>

  <Step title="Add a learner if needed">
    ```bash
    curl "https://dash.trainertwin.com/api/v1/users" \
      --request POST \
      --header "x-api-key: $TRAINERTWIN_API_KEY" \
      --header "content-type: application/json" \
      --data '{ "email": "learner@example.com" }'
    ```

    Keep the returned `user.id` for the following requests. A new learner receives 30 starting credits once; a repeat
    add returns the same learner without allocating again. There is no invitation acceptance step.
  </Step>

  <Step title="Read or add learner credits">
    `GET /credits` shows your available org balance. `GET /users/{id}/credits` shows one learner's allocation and usage.
    To give an existing learner more minutes, use a fresh key for this intended grant and reuse it on retries:

    ```bash
    curl "https://dash.trainertwin.com/api/v1/users/user_123/credits" \
      --request POST \
      --header "x-api-key: $TRAINERTWIN_API_KEY" \
      --header "Idempotency-Key: grant-module-2-user-123" \
      --header "content-type: application/json" \
      --data '{ "minutes": 30, "note": "Extra practice" }'
    ```

    This spends existing org credits, not money or newly minted credits. See [Credits](/guides/credits).
  </Step>

  <Step title="Assign a published scenario">
    Use a learner ID returned by the users endpoint and a published scenario slug from your TrainerTwin dashboard.

    ```bash
    curl "https://dash.trainertwin.com/api/v1/assignments" \
      --request POST \
      --header "x-api-key: $TRAINERTWIN_API_KEY" \
      --header "content-type: application/json" \
      --data '{
        "userId": "user_123",
        "scenario": "react-mock-interview"
      }'
    ```
  </Step>
</Steps>

## Postman collection

Download the <a href="/trainer-twin-api.postman_collection.json" download>TrainerTwin API Postman collection</a> and import it into Postman (`File → Import`). Then set the `apiKey` collection variable to your `tt_...` key — every request already sends it in the `x-api-key` header.
