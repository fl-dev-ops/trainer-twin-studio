# Learner portal

> The learner portal is an organization's public home and its practice pages. Visitors can see the trainers; signed-in learners see their access and practice minutes, open a twin or assigned role play, talk, and give feedback. `/t/<path>` keeps the twin profile, call and summary on one page. `/s/<code>` checks a practice code and uses a separate device/document check before the call. The portal does not offer studio navigation. Sources: `web/lib/pages/org-home.ts` `loadOrgHome`, `web/lib/pages/learner.ts` `loadTwinLink` / `loadSharedSession`, `web/components/twin/twin-learner-flow.tsx`, `web/components/session-view.tsx`.

## Who uses it

| Person | What they can do here | Source |
| --- | --- | --- |
| Signed-out visitor | Read the org home and twin profile. Sign in with Google there or follow the email-code sign-in link. A practice-code page sends them to sign-in first. | `web/components/org/org-home.tsx` `OrgHome`; `web/components/twin/twin-learner-flow.tsx` `TwinLearnerFlow`; `web/lib/pages/learner.ts` `loadSharedSession` |
| Learner (`member.role = "user"`) | See their role plays and twin access, use their own minutes, switch account, call and submit feedback. Role-play assignees are already members; opening an active common twin-code page adds the signed-in existing account and its assignment before prejoin. | `web/lib/pages/org-home.ts` `loadOrgHome`; `web/lib/pages/learner.ts`; `web/lib/interview-sessions.ts` `activateSession` |
| Org admin or team member | Preview the learner home and `/t` flow without learner metering; billed voice calls use org credits. On `/s`, minutes are also hidden, but code ownership is still checked. | `web/lib/pages/learner.ts` `isStudioMember` / `twinAccessFor` / `loadSharedSession` |

[Practice](practice.md) sets twin practice, role-play rules 17–21 and ending/token rules 22–28; [People](people.md) sets membership and Refusals. Studio management is not a learner capability. The exact enforced guards and gaps are described under Rules and Mismatches; see [Organizations and roles](orgs-and-roles.md).

## How it works

### Org home: signed out, signed in, preview

1. The org route layout looks up the first host label, applies the org accent and renders browser-only pages. A missing org redirects to `/auth/sign-in`. The home page separately renders **Organization not found** if its loader returns `notFound`. Page data comes through `page.orgHome`, not server-rendered learner content. (`web/app/(org)/layout.tsx`; `web/app/(org)/page.tsx`; `web/lib/pages/router.ts` `orgHome`.)
2. loadOrgHome resolves account identity and host org, then determines enabled studio role with orgPerson. It performs no member creation or invitation acceptance. Everyone added is already a member (`web/lib/pages/org-home.ts`; `web/lib/pages/learner.ts` `isStudioMember`; `web/lib/org-people.ts`).
3. Home loads this org's unarchived own-persona twins oldest first. Main twins become trainer entries; skill twins on that same persona become topic names. The first main twin is featured. If there is no main twin, the oldest own persona supplies a trainer-only profile; if there is no such persona, the org name and a practice introduction are shown. (`web/lib/pages/org-home.ts` agent/ownPersona queries; `web/components/org/org-home.tsx`.)
4. Signed out: show the trainer/profile/topics, other trainers and valid website link, **Sign in to start**, and a Google button plus EmailCodeSignInLink. No personal minutes or role plays are shown. Sign in or **Start conversation** opens a Google sign-in dialog; the callback is this org's `/`. A Google client error is inline; OAuth refusals return to sign-in with a message and safe return URL (`web/app/auth/sign-in/page.tsx`). (`web/components/org/org-home.tsx` `OrgHome`; `web/components/auth/google-sign-in-button.tsx`.)
5. Signed in as learner: each twin gets its own access result. The main twin shows either **You're in, {first name}** and `{left} of {total} min left`, or the blocked title/reason and signed-in email. A usable main twin's dock opens its `/t` page. Clicking any of its topic names opens that same main twin, not a skill-specific page. Other trainers show **Talk** or their blocked title. (`web/lib/pages/learner.ts` `twinAccessFor`; `web/components/org/org-home.tsx` `start` / `OtherTrainer`.)
6. **Your role plays** lists this person's `pending` and `used` assignments, newest assigned first. Ownership is required member.userId, never email. Each shows name, optional objective, and **Start role play** to `/s/<shareCode>`. Signed-out visitors, studio members and `hideRoleplay` orgs get no list. Expiry dates are passed to the UI but neither filtered nor displayed. (`web/lib/pages/org-home.ts` roleplays query; `web/components/org/org-home.tsx`.)
7. A studio member sees **Preview** and the no-minutes explanation; role plays are not listed. A learner without usable content sees **Nothing assigned to you yet**, unless the main twin's more specific blocked message takes precedence. The account menu offers **Switch account**. Home/twin switching signs out, refreshes page queries, then opens the Google dialog even if sign-out rejects. (`web/components/org/org-home.tsx`; `web/components/twin/twin-learner-flow.tsx` `switchAccount`; `web/lib/use-refresh.ts`.)

### Readable twin page: `/t/<path>`

1. Resolve the org from the host. Trim/lowercase the path; resolve an own persona's main twin first, then an org-prefixed short slug, then the full slug. Only `TWIN`, unarchived agents in this org qualify. A missing twin shows **Twin not found** with instructions to ask for a new link. (`web/lib/twin-access.ts` `resolveTwinPath`; `web/lib/pages/learner.ts` `loadTwinLink`; `web/app/(org)/t/[slug]/page.tsx`.)
2. Trainer name/title/bio and the twin name/description are public. Avatar GET URLs are presigned for one hour; signing failure gives no photo rather than failing the page. Signed-out visitors see **Start conversation** and a Google dialog with an email-code link returning to the same `/t` path. (`web/lib/pages/learner.ts` `trainerProfile` / `twinProfile`; `web/components/twin/twin-learner-flow.tsx`.)
3. `twinAccessFor` calls practicePerson (enabled database membership), then assertLiveTwin (same-org, TWIN, not archived), separately gets the learner's usable personal assignment code, then calls `startAllowance` (local pause, learner/org five-minute floor; free unbilled studio). Admin/team need no assignment but can be refused for pause or org credits. This path never joins or gives credits. It maps no_org → notMember, twin_not_assigned → unassigned, revoked/ended → ended, credits_out (under 60 seconds) → used. Other AppErrors, including credits_short (60–299 seconds), member_disabled and studio credit refusals, become blocked. Every refusal is `ok: false` with message; allowed learners get floored balance/total grants. Home reuses the same helper. (`web/lib/pages/learner.ts:190–219`; `web/lib/practice.ts` `practicePerson`, `startAllowance`; `web/lib/pages/org-home.ts:41`.)
4. Allowed learners see the whole-minute meter and **Start voice call**. Blocked learners see the copy in the table below and no call dock. A click opens `CalibrationCall` in learner mode, using the personal code; preview passes no code and starts by agent slug. There is no `/s` prejoin, camera preview, pre-call document selection or screen-share request here. (`web/components/twin/twin-learner-flow.tsx`; `web/components/calibration/calibration-call.tsx` `start`.)
5. The shared call component starts the room during a get-ready countdown, then enables the mic and releases the opening once the agent is present. The learner sees the portrait, elapsed time, an estimated remaining-minute label, conversation, mute, typed-message composer, optional file attachment, report-issue and end controls. Calibration turn ratings and answer-evidence controls are hidden for learners. Start/connection errors offer **Try again**; microphone failure gives a toast with recovery instructions. (`web/components/calibration/calibration-call.tsx` `start` / `tryRelease`, learner rendering.)
6. Ending a live call asks for confirmation. A learner's confirmed end and the agent's completed event finalize as `completed`; unexpected disconnect/unmount uses `abandoned`. Save errors give a toast but still leave the call. On end, the parent refreshes access/minutes and shows a summary with duration, local transcript and remaining minutes. **Start another** returns to the profile, disabled below MIN_START_MINUTES=5 whole minutes. There is no explicit **Back to home** action on this twin summary. (`web/components/calibration/calibration-call.tsx` `end` / `closeSession`; `web/components/twin/twin-learner-flow.tsx` `Summary`.)
7. Summary feedback is optional: select 1–5 stars, optionally write up to 500 characters, then **Send rating**. No session ID means sending is disabled. Success shows **Sent** and disables editing; failure is a toast. **Report a problem** is also available during the call, without intentionally ending it, and on the summary. Select one or more reasons or enter at least five trimmed characters; free text is limited to 2,000 characters. The POST includes the session ID if available, page URL and PostHog replay URL. Success shows **Thanks for flagging it**. Issue storage/alerts belong to [Platform](platform.md). (`web/components/twin/twin-learner-flow.tsx` `Summary` / `ReportDialog`; `web/components/calibration/calibration-call.tsx` learner report control.)

It is not used on switch-account or normal session completion. (`web/components/session/home-redirect.tsx`.)

### `/s` prejoin: minutes, devices, documents and screen sharing

1. The allowed page supplies one agent/persona, scenario name, user/org branding, intro video/photo, upload settings and code to `SessionView` with `autoStart: true`. It still waits for prejoin; opening the link alone does not start a call. An org logo is passed only for PNG/JPEG/WebP base64 data URLs. (`web/lib/pages/learner.ts` `twinSessionView` / `loadSharedSession`; `web/components/session-view.tsx`.)
2. Prejoin shows the scenario and, when non-null, **{n} min of practice left · the call ends when they run out**. It requests microphone and camera separately, shows a preview, allows toggles and microphone/speaker/camera selection, and releases preview tracks on join/unmount. Both devices initially default on when available. Either device can fail independently. Denied/unsupported access offers **Try device check again**; denied devices do not prevent joining with devices off. Only an in-progress check or missing required document disables **Join session**. (`web/components/session/prejoin.tsx` `startPreview` / `join`.)
3. Document card appears only when required or offered. It shows the configured label/instruction, or **Documents**, plus **Required** or **Optional**. Pick/drop one PDF or PNG/JPEG/WebP image up to 10 MiB. Upload errors stay in an alert. A successful upload shows filename, size, thumbnail, **Attached** and **Remove**. Remove clears selection, not the saved upload. The prior-context prop is unused; there is no chooser for earlier uploads on prejoin. (`web/components/session/prejoin.tsx`; `web/lib/context-upload.ts` `beforeUploadProblem`.)
4. Upload uses `POST /api/uploads`, direct presigned S3 PUT, then complete. An enabled org member may upload. Common-link page opening has already added the learner, so normal prejoin uploads use that same membership. Direct uploads now require enabled org membership; there is no nonmember/common-code fallback (`web/lib/upload-access.ts:8–13` `uploader`). Role-play email invitation upload checks are gone. Upload ownership, byte validation and session binding are handled outside the portal; see [Platform](platform.md) and [Sessions](sessions.md). (`web/lib/upload-client.ts` `uploadFile`; `web/lib/upload-access.ts` `uploader`.)
5. Agents using `before` settings have optional pre-upload and screen sharing only when switched on; mid-call upload follows `duringUpload`. Twins default all these switches off. Legacy role plays without `before` use required-context rules, always require screen sharing, and do not allow mid-call attachments. (`web/lib/context-upload.ts` `usesBeforeSettings` / `contextUploadFromAgentData` / `resolveContextUpload`; `web/components/session-view.tsx` resolved settings.)
6. When sharing is required, prejoin says **Entire Screen Required** and explains tabs/windows will be rejected. The actual browser picker opens after room connection, not on prejoin. Only `displaySurface === "monitor"` qualifies. A tab/window or unverifiable share is stopped. Denial or later stopping opens a blocking **Share your entire screen** overlay with a retry button. This is a browser UI gate, not a claim that the server verifies screen sharing. (`web/components/session-view.tsx` `enableWholeScreenShare`, share-state effects and blocking overlay.)

### `/s` call, end, feedback and repeat practice

1. **Join session** passes selected device IDs/toggles and one document ID. A five-second **Get ready** countdown starts session creation with the share code, document IDs and `holdOpening: true`. Once connected, countdown finished, agent present and any intro video finished, the page applies mic/camera settings and sends `begin-opening`. Intro download failure falls back to streaming; autoplay can require a tap/unmute. (`web/components/session-view.tsx` `handleStartSession`, countdown/release effects, `ScenarioIntro`.)
2. [Sessions](sessions.md) re-runs the same role-play helper; new creation rechecks person/link status/agent archive under the minutes lock, with document checks before it. Learners cannot start by name or deploymentKey, and Start adds no member. A matching live role-play call conditionally resumes inside the lock with its original deadline; ended calls start fresh. Resume's lock does not repeat access (Mismatches). Twins always start fresh. No activation/end/failure writes role-play used status. Resumed LiveKit join failure leaves the original call live; `DUPLICATE_IDENTITY` disconnect in the displaced tab is ignored rather than ending it. (`web/lib/interview-sessions.ts:220–303,324–416`; `web/lib/session-activation.ts:131–143`; `web/components/session-view.tsx:924–929`.)
3. The call shows trainer/candidate tiles, elapsed time, audio, captions, optional chat (desktop sidebar/mobile sheet), camera/mic, audio unlock and confirmed end controls. The agent can display code, choice, whiteboard, PDF, image or presentation workspaces. When enabled, file attachment uploads and links the file to this session before sending its marker to the conversation. During-call rules are images up to 5 MiB or PDFs up to 10 MiB. The header has a generic report-issue button; the learner logo is not a studio/home link. (`web/components/session-view.tsx`; `web/components/session/session-control-bar.tsx`; `web/lib/context-upload.ts` `duringUploadProblem`; `web/components/report-issue-button.tsx`.)
4. Creation/connection failure shows **Session problem** with **Try again**. Confirmed manual end saves as `abandoned`; the agent's completed event saves as `completed`; ordinary room disconnect uses `abandoned` (near-deadline nonmanual ends can be `time_up`/completed). `DUPLICATE_IDENTITY` does not finalize. Finalization sends only sessionId/status/captured transcript, never evidence or transcriptFinal. keepalive is enabled only below 60,000 serialized characters; larger calls use a normal request. Server finalize checks the owner, enabled membership, deletedAt and ≤1,048,576 UTF-8 bytes; memory runs in after(). See [Sessions](sessions.md#3-end-the-call-and-save-transcriptevidence). If save fails, stay on the error screen with **Could not save session** and retry the pending save before disconnect/reset. (`web/components/session-view.tsx` `handleStartSession` / `handleDisconnect` / `finalizeSession`.)
5. A normal/manual code-session end with a session ID shows feedback: **{scenario} ended**, saved-responses copy, rating 1–5, optional note up to 500 characters, **Send feedback**, and **Skip and practise again**. Failure shows an inline error and retains the form. Success shows **Thanks for your feedback** and **Want another go? Practise again as long as you have minutes.** (`web/components/session-view.tsx` `SessionFeedback`.)
6. Unexpected disconnect skips feedback: **Session ended**, explanation that the connection closed and captured data was saved, plus repeat/home actions. Successful feedback also exposes **Back to home** (`/`) and **Practise again** (full page reload). Skipping feedback also reloads immediately. Reload rechecks account/access/balance and can show out-of-minutes instead of prejoin. Before submitting feedback, the form has no explicit home button. (`web/components/session-view.tsx` ended branch / `PractiseAgainActions` / `SessionFeedback`.)

## Rules

1. Portal home and readable twin profiles are public; a practice-code page requires sign-in before code validation. Org identity is host-based, not selected by a learner request parameter. (`web/lib/session-user.ts` `resolveSessionUser`; `web/lib/pages/router.ts` public portal procedures; `web/lib/pages/learner.ts`.)
2. Home does not accept invitations or create membership. Assigned role plays use required member.userId for the signed-in account (`web/lib/pages/org-home.ts`; `web/lib/org-people.ts`).

## Edge cases and limits

- The home does not list skill-only assignments as independent cards. It lists all own-persona main twins, even blocked ones, and topics underneath the main trainer. A learner with only a skill assignment may still need the direct `/t` or `/s` link. (`web/lib/pages/org-home.ts` all-skills filter; `web/components/org/org-home.tsx`.)
- `viewer.minutesLeft` is loaded for a non-studio home visitor but not rendered independently. Only an allowed main twin renders the home minute meter. A role-play-only learner sees their minutes after opening the practice link. (`web/lib/pages/org-home.ts` minutesLeft; `web/components/org/org-home.tsx` meter branch.)
- `/t` pre-call switches are not wired into its call except `duringUpload`: `twinProfile` passes only `attach`, and `CalibrationCall` has no prejoin document/screen-share flow. `/s` does receive the full resolved settings. (`web/lib/pages/learner.ts` `twinProfile` / `twinSessionView`; `web/components/twin/twin-learner-flow.tsx`; `web/components/calibration/calibration-call.tsx`.)
- `/t`'s header minute badge is a prop snapshot; the portrait estimates `initial minutes - ceil(elapsed seconds / 60)`. On summary the displayed session minutes are `max(1, ceil(local seconds / 60))`, not a ledger receipt. End triggers an asynchronous server refresh. (`web/components/twin/twin-learner-flow.tsx` topBar / `Summary`; `web/components/calibration/calibration-call.tsx` portrait.)
- A disabled common link fails even for someone with an assignment when opened through that common code. Their personal code or `/t` assignment access is checked separately. (`web/lib/twin-access.ts` `twinAccessByCode`: link status precedes existing-assignment lookup.)
- Role-play link pages now refuse disabled membership, closed links, archived agents, inactive/voice-disallowed deployments, pause and short credits before prejoin. Minutes are still a whole-number display, not permission. A still-live call is not detected on page load: pause/short credits may block reload even though Start would resume it. Uploader separately checks enabled membership. (`web/lib/pages/learner.ts:88–111`; `web/lib/roleplay-access.ts:22–40`; `web/lib/interview-sessions.ts:282–298`; `web/lib/upload-access.ts`.)
- After a call, refreshed refused access has minutesLeft=null in TwinLearnerFlow. Summary's Start another may remain enabled, but only returns to the blocked profile, which has no call dock; it is not a direct new Start. (`web/components/twin/twin-learner-flow.tsx:75–76,168,315`; `web/lib/pages/learner.ts:218`.)
- Page-load failures outside the explicit access variants propagate to the app error boundary, with **Something went wrong** and **Try again**; they are not automatically classified as invalid codes. (`web/lib/api.ts` `useApi`; `web/app/error.tsx`; `web/lib/pages/learner.ts` error handling.)

## Open questions

1. Should common-link joining require a confirmation button? [Practice](practice.md#open-questions) leaves this open; loading page.sharedSession currently commits it before prejoin (`web/lib/pages/learner.ts:102`; `web/lib/twin-access.ts:167–178`). People already decides learner studio access; remaining page-refusal gaps are bugs above, not an undecided role policy.
2. Should `/t` honour `preUpload` and `preScreenshare`, or deliberately remain a voice-only immediate start? `plans/twin-wiring-and-reliability.md` expects these settings on learner calls; `web/lib/pages/learner.ts` `twinProfile` and `web/components/calibration/calibration-call.tsx` do not implement that prejoin path.
3. Should both end paths preserve the screen on a failed save? `web/components/session-view.tsx` retries before leaving, while `web/components/calibration/calibration-call.tsx` end shows a toast and still opens the twin summary.
