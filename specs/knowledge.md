# Knowledge

> Knowledge stores an organization's source files and makes their text available to the studio, the copilot and conversation agents. PostgreSQL holds the records, S3 holds files, and Chroma holds searchable text chunks and their embeddings. There are two ingestion contracts in the web app: the current Python file worker and an older job/work-item queue. They are not interchangeable; Notion and the older knowledge-base upload API still send messages the current worker cannot process. (`web/lib/org-knowledge.ts`, `web/lib/specs.ts`, `web/lib/ingestion-queue.ts`, `ingestion/src/ingestion/worker.py`.)

## Who uses it

| User | What the code lets them do |
| --- | --- |
| Org admin and team | Upload, reindex, import, connect accounts, refresh sources, delete documents/sources and disconnect accounts. Both roles pass `getTrainerOrg`. (`web/lib/org.ts`, `web/app/api/knowledge/upload/route.ts`, `web/lib/connectors.ts`.) |
| Signed-in org member, including learner (`user`) | The direct document list, stats, previews, chunks and search routes use `getSessionOrg`, not the studio-only guard. The older catch-all API also lets this guard create, upload, digest and delete. This is broader than the studio UI's purpose. (`web/app/api/knowledge/documents/route.ts`, `stats/route.ts`, `documents/[id]/preview/route.ts`, `documents/[id]/chunks/route.ts`, `search/route.ts`, `[[...kb]]/route.ts`, all under `web/app/api/knowledge/`; `web/lib/org.ts`.) |
| Copilot | Downloads the org's Markdown copies into its sandbox to build skills/role plays. It does not need Chroma indexing to list a Markdown copy. (`web/app/api/internal/knowledge-sources/route.ts`; see [Copilot](copilot.md).) |
| Chat brain / voice conversation | The chat brain calls the secret-authenticated studio endpoint for search and full-document reads. The Python voice agent is not the knowledge store. Different agent modes use different material, described below. (`chat/agent/tools/search_knowledge.ts`, `chat/agent/tools/read_knowledge_document.ts`, `web/app/api/copilot/studio/route.ts`; see [Voice agent and chat](voice-agent-and-chat.md).) |
| Ingestion worker / cron / operator | The worker reports file results; the cron republishes unsent old-style work items; migration scripts can provision databases and rebuild indexes. (`ingestion/src/ingestion/worker.py`, `web/app/api/internal/ingestion/{results,pump}/route.ts`, `web/scripts/migrate-knowledge.ts`.) |

Role selection and enabled memberships belong to [Orgs and roles](orgs-and-roles.md). Knowledge's HTTP guards return 401 when their required org/member is absent. (`web/lib/org.ts`, `web/app/api/knowledge/upload/route.ts`.)

## Words used here

| Term | Meaning |
| --- | --- |
| Knowledge base / KB (`KnowledgeBase`) | An org-owned named group of documents; `slug` is its readable identifier. (`web/prisma/schema.prisma`.) |
| Document (`KnowledgeDocument`) | One original file plus optional converted Markdown and searchable chunks. It is not a learner's `ContextDocument` upload. (`web/prisma/schema.prisma`; see [Platform](platform.md) for conversation uploads.) |
| Source (`KnowledgeSource`) | A repeatable import identity: KB + connector + external resource. One source can own several documents. Current ordinary uploads have no source row. (`web/lib/ingestion-queue.ts` `defaultIdentityKey`, `enqueueIngestionWork`; `web/lib/org-knowledge.ts` `uploadDocument`.) |
| Connector / connection | A connector is an acquisition method (`upload`, `notion`, `notion_public`, `youtube`). A connection holds an authorized Notion workspace or YouTube channel's credentials. Drive instead uses a temporary browser session. (`web/prisma/schema.prisma`, `web/lib/google-drive.ts`.) |
| Job / work item / outbox | The older durable import job, its individual tasks, and queued tasks whose SQS publication has not been recorded (`enqueuedAt = null`). Current file messages do not create these rows. (`web/lib/ingestion-queue.ts`.) |
| Chunk / embedding | A piece of converted text / a numeric vector representing that text for similarity search. (`ingestion/src/ingestion/__init__.py`, `web/lib/main-collection.ts`.) |
| Tenant / database / collection | Chroma's storage hierarchy. The configured tenant is shared; each immutable org ID has its own database; `main` is the shared collection name inside each org database. (`web/lib/chroma-tenant.ts`, `web/lib/main-collection.ts`.) |
| Indexed | A document has completed indexing according to its DB status. Search itself reads Chroma, not a per-hit DB status check. (`web/app/api/internal/ingestion/results/route.ts`, `web/lib/main-collection.ts` `searchKnowledge`.) |
| PII | Personally identifying information. The worker asks a model to identify spans and replaces exact text with placeholders before chunking. Originals remain stored unchanged. (`ingestion/src/ingestion/chef.py`, `vendor/pii_redact.py` in the same directory; `web/lib/org-knowledge.ts`.) |

## Data

The records below are defined in `web/prisma/schema.prisma`. Status fields are strings, not Prisma enums; comment lists describe expected values, not enforced enum validation.

| Record | Fields, constraints and writers |
| --- | --- |
| `KnowledgeBase` | `id`, nullable legacy `orgId`, `slug`, `name`, `createdAt`; unique `(orgId, slug)`. Written by `web/lib/specs.ts` `createKnowledgeBase` and `web/lib/org-knowledge.ts` `getOrCreateOrgKnowledgeBase`. Org deletion cascades to its bases. |
| `KnowledgeDocument` | KB, optional `sourceId`/`externalId`, external update/parent fields, unique `(kbId, slug)` and `(sourceId, externalId)`, title, extension, original byte size, `s3SourceKey`, optional `s3MarkdownKey`/`s3QuestionsKey`, status/error, `indexedAt`, timestamps. Written by upload/import helpers and results route. KB deletion cascades; source deletion alone sets `sourceId` null, though `deleteSource` explicitly deletes documents first. |
| `KnowledgeSource` | Org/KB, connector, external ID, globally unique `identityKey`, source URL, status/error, `lastSyncedAt`, timestamps. `enqueueIngestionWork` and `queueYouTubeSync` write `syncing`; current file results do not set it back to `active` or update `lastSyncedAt`. (`web/lib/ingestion-queue.ts`, `web/lib/youtube-ingestion.ts`, `web/app/api/internal/ingestion/results/route.ts`.) |
| `NotionSourceConfig` / `YouTubeSourceConfig` | One config per source. Notion: optional connection and `accessMode` (`owned`/`public`). YouTube: required connection, optional caption ID/update and fetched time retained from the older pipeline. Written on source creation. (`web/lib/ingestion-queue.ts`, `web/lib/youtube-ingestion.ts`.) |
| `IngestionJob` | Source, `activeKey`, status/stage/error, discovered/processed counters and start/finish timestamps. At most one queued/running job per source, enforced by a partial unique index. (`web/lib/ingestion-queue.ts`; `web/prisma/migrations/20260911000000_add_ingestion_active_index/migration.sql`.) |
| `IngestionWorkItem` | Job, unique `(jobId, workKey)`, kind (`resource`, `segment`, `publish`), parent, JSON payload, artifact key/hash, chunk/attempt counts, lease/enqueue/process timestamps, status/error. Web enqueues these; the current Python worker has no DB work-item handler. (`web/lib/ingestion-queue.ts`, `ingestion/src/ingestion/worker.py`.) |
| `NotionConnection` / `YouTubeConnection` | Org, authorizing user, workspace/channel identity and display details; encrypted access/refresh tokens and expiry. Unique `(orgId, workspaceId)` / `(orgId, channelId)`. YouTube also stores status, refresh lease and verification time. Written by OAuth helpers; YouTube's token store refreshes credentials. (`web/lib/notion-oauth.ts`, `web/lib/youtube-oauth.ts`, `shared/youtube/connection-store.server.ts`.) |
| `NotionOAuthState` / `YouTubeOAuthState` | Random state bound to org/user/KB, expiry, consumption time; YouTube also stores the PKCE verifier. OAuth helpers write them. (`web/lib/notion-oauth.ts`, `web/lib/youtube-oauth.ts`.) |

Lifecycles:

- Ordinary upload: `uploading → uploaded` (no queue) or `queued → digesting → indexed`; S3 failure or a final worker failure gives `failed`. A queue-send error keeps `uploaded` with an error. Reindex sets `queued`. (`web/lib/org-knowledge.ts` `uploadDocument`, `reindexDocument`; results route.)
- YouTube: document `fetching → queued` on the `fetched` callback, then the file lifecycle above. The import response says `queued` after dispatch, but the stored document stays `fetching` until that callback. Missing queue sets `failed`. (`web/lib/youtube-ingestion.ts` `queueYouTubeSync`; results route.)
- Older jobs: expected `queued → running → succeeded/failed`; work items also allow `pending`. Source comments list `active`, `syncing`, `failed`, `unavailable`, `expiring`. These are not evidence that the current worker performs those transitions. (`web/prisma/schema.prisma`, `ingestion/src/ingestion/worker.py`.)
- YouTube connections use `active`, `reconnect_required`, and checks for `disconnecting`/`disconnected`; current disconnect hard-deletes rather than running a background disconnect lifecycle. (`web/lib/youtube-oauth.ts`, `shared/youtube/tokens.server.ts`, `web/lib/connectors.ts`.)

Storage layout (`orgPrefix` means `${S3_BASE_PREFIX}/${orgId}`; default base prefix `trainertwin-dev`):

| Artifact | Location / metadata |
| --- | --- |
| Current original | `<orgPrefix>/knowledge/files/<docId>/<slug>`. (`web/lib/org-knowledge.ts`.) |
| Worker output | `<orgPrefix>/ingest/files/<docId>/content.md` and `chunks/part-NNNN.jsonl`. Chunk files include offsets, token counts and embeddings. (`web/app/api/internal/ingestion/results/route.ts`.) |
| Older original + Markdown | `<orgPrefix>/knowledge/<kbId>/<docId>/source-<slug>` and `content.md`. Existing keys remain valid. (`web/lib/specs.ts` `uploadKnowledgeFile`; `web/lib/s3.ts` `kbPrefix`.) |
| Chroma knowledge chunk | ID `kb_<docId>#<index>`, text, vector, metadata `type: knowledge`, org/KB/doc IDs, source slug, title, chunk index; worker writes also include `chunkingVersion`. (`web/lib/main-collection.ts` `ingestKnowledgeDoc`, `upsertKnowledgeChunks`.) |

Agent/skill source attribution (`SkillSource`) and generated skill artifacts belong to [Twins](twins.md) and [Roleplays](roleplays.md), not the source document's lifecycle. (`web/lib/skill-sources.ts`, `web/lib/scenario-ingest.ts`.)

## How it works

### Bases and file uploads

1. The current upload route accepts multipart `file` and calls `OrganizationKnowledgeService.uploadDocument`. It uses the org's oldest KB, creating `<org slug>-knowledge` (or `organization-knowledge`) if none exists. It does not let this request select another KB. (`web/app/api/knowledge/upload/route.ts`, `web/lib/org-knowledge.ts` `getOrCreateOrgKnowledgeBase`.)
2. Validate extension, nonzero size and maximum size before creating the document. Sanitize the filename stem, retain its last 120 characters, and append `-1`, `-2`, etc. on slug collisions within that KB. The initial title replaces hyphens/underscores with spaces. This is filename separation, not byte-content deduplication. (`web/lib/org-knowledge.ts` `uploadDocument`.)
3. Create an `uploading` row, save the original once in its own S3 directory, then send a file message with a 24-hour signed GET URL. No Markdown is produced in this HTTP upload request. A failed S3 write records its cleanup key, `failed` and the error, then throws. A missing queue keeps the stored file `uploaded`; a thrown queue error keeps it `uploaded` with a retry message. The response's `jobId` is null even for a queued upload. (`web/lib/org-knowledge.ts` `uploadDocument`; `web/lib/ingestion-queue.ts` `queueKnowledgeFile`.)
4. The older `/api/knowledge/<kb>` upload calls `specs.ts` `uploadKnowledgeFile`: create/resolve the named base, convert documents synchronously with `documentToMarkdown`, save original plus Markdown under `kbPrefix`, provision Chroma, and enqueue an identifier-only job. It marks the document `queued` even when SQS is unconfigured. `digestKnowledge` uses the same older contract, skips `digesting` documents and documents without a usable Markdown key. It may return zero queued jobs after skipping keys. See the worker incompatibility below. (`web/app/api/knowledge/[[...kb]]/route.ts`, `web/lib/specs.ts`, `web/lib/documents.ts`.)

### Notion: authorize, import, refresh

1. OAuth start creates a ten-minute state bound to the org, user and KB and returns Notion's authorization URL. On a successful callback, an atomic SQL update consumes a still-unused/unexpired state only when KB ownership and an admin/team membership match. It exchanges the code and upserts the org's workspace connection. Provider-error callbacks redirect before consumption. (`web/lib/notion-oauth.ts`; `web/app/api/connectors/notion/oauth/{start,callback}/route.ts`.)
2. Tokens are AES-256-GCM encrypted with a base64 32-byte `NOTION_TOKEN_ENCRYPTION_KEY` and authenticated binding `orgId:userId:connectionId`. Refresh-token/expiry fields can be saved, but no current Notion token-refresh or crawl implementation exists in `ingestion/`. (`web/lib/notion-token.ts`, `web/lib/notion-oauth.ts`, `ingestion/src/ingestion/worker.py`.)
3. `notionImportSchema` distinguishes OAuth imports (connection required) from public imports (no connection field allowed). Public URLs must use HTTPS, approved Notion hosts, no credentials or explicit port. Page-ID parsing accepts a UUID/compact ID or extracts the last such ID in a URL. (`web/lib/notion.ts`.)
4. `queueNotionSync` verifies an owned connection belongs to the org, resolves a KB/default, creates/reuses a source by `kbId:connector:pageId`, and queues a root `resource` work item. Refresh repeats this with the stored URL and access mode. Both return accepted queue metadata, not imported pages. The Python worker cannot consume this message, so a completed Notion import cannot be specified from this code. (`web/lib/notion-ingestion.ts`, `web/lib/connectors.ts` `refreshSource`, `web/lib/ingestion-queue.ts`, `ingestion/src/ingestion/worker.py` `parse`.)

### YouTube: authorize, import, refresh

1. OAuth requests `youtube.force-ssl`, offline access, consent/account selection and PKCE. State expires in ten minutes and is consumed once before code exchange, including cancellation. It lists owned channels and upserts a connection per org/channel. A refresh token must be returned or already stored; no owned channel or a concurrent disconnect refuses completion. Tokens stay server-side and are encrypted with org/user/connection binding. (`web/lib/youtube-oauth.ts`, `shared/youtube/http.server.ts`, `shared/youtube/tokens.server.ts`.)
2. Authorized Google calls reuse access tokens valid for more than 60 seconds. Expired tokens use a DB refresh lease; another refresher yields retryable `REFRESH_BUSY` rather than waiting. An unauthorized operation expires the token and retries once; invalid background authorization can set `reconnect_required`. (`shared/youtube/tokens.server.ts`, `shared/youtube/connection-store.server.ts`.)
3. Preview/import require an active connection in this org and an individual video ID/URL. Using that connection's authorizing user, verify the channel still belongs to the account and owns the video. Private videos are refused before storing anything; public/unlisted videos can be fetched without owner cookies. Without `refresh`, an already indexed YouTube document in the KB returns immediately. (`web/lib/youtube.ts`, `web/lib/youtube-ingestion.ts`, `shared/youtube/client.server.ts` `verifyOwnedVideo`.)
4. Upsert the source and document, set `fetching`, and queue a `type: fetch` message with a signed S3 PUT. The worker uses yt-dlp (720p-preferred MP4, no playlists), uploads the downloaded file, and reports `fetched`. The results route records size and queues normal file processing against the stored original. This path uses neither caption extraction nor `IngestionJob` rows. (`web/lib/youtube-ingestion.ts` `queueYouTubeSync`, `web/lib/ingestion-queue.ts` `queueVideoFetch`, `ingestion/src/ingestion/fetch.py`, results route.)
5. Refresh resolves the document/source's active connection and repeats import with `refresh: true`, reusing the source/document identity. Source-level refresh does the same. There is no scheduled knowledge-source refresh in `web/vercel.json`. (`web/lib/youtube-ingestion.ts` `refreshYouTubeDocument`, `web/lib/connectors.ts` `refreshSource`.)

### Google Drive: a snapshot, not a synced connection

1. Start OAuth with only `drive.file`, PKCE and online access. Encrypted HttpOnly, SameSite=Lax cookies bind the ten-minute state to org/user. Callback checks that state, scope and verifier, clears the state cookie, and saves an access cookie for at most one hour. No refresh token or connection row is stored. An access token with 30 seconds or less remaining is rejected. (`web/lib/google-drive.ts`; `web/app/api/connectors/google-drive/oauth/{start,callback}/route.ts`.)
2. The private, uncached session endpoint exposes only the short-lived token, Picker API key and project number to the studio browser. Google Picker supports multi-selection; tokens are not saved in localStorage. Import/start/forget mutations verify the configured studio Host and browser Origin. (`web/app/api/connectors/google-drive/session/route.ts`, `web/lib/google-drive-picker.ts`, `web/lib/google-drive.ts` `assertDriveOrigin`.)
3. Import accepts only `{fileId}`. Fetch metadata and bytes from fixed Google API URLs, not browser-supplied URLs, names, sizes or MIME types. Reject disabled downloads, unsupported files and excessive declared/streamed sizes. Docs, Sheets and Slides export to DOCX, XLSX and PPTX; other supported documents keep their bytes. (`web/lib/google-drive.ts` `downloadDriveFile`.)
4. After downloading/checking access even for repeats, reuse an org document only when `externalId = google-drive:<id>` and status is `uploaded`. Otherwise call the ordinary upload service and attach this external ID. There is no `KnowledgeSource` for Drive; it displays as an upload with a derived Drive link. Reindex processes the saved copy, not the current Drive original; reconnect and import to fetch a new snapshot. Forgetting access clears the cookie only. (`web/app/api/connectors/google-drive/import/route.ts`, `web/lib/org-knowledge.ts` `getAllDocuments`, `reindexDocument`; Drive session DELETE.)
5. The UI sends one import request per selected pending/failed file and can retry partial failures. A localhost callback bridge exists only for local development; it forwards bounded code/state/error fields to a fixed HTTPS studio, which still performs normal authorization. (`web/components/knowledge/google-drive-import.tsx`, `web/app/api/connectors/google-drive/oauth/local-callback/route.ts`, `web/lib/google-drive.ts`.)

### Queue, worker and results

There are two separate contracts in `web/lib/ingestion-queue.ts`:

| Producer | SQS payload and recovery |
| --- | --- |
| `queueKnowledgeFile` / `queueVideoFetch` | File identifiers, org/KB, filename + signed GET; or fetch URL + signed PUT. URLs last 24 hours. No durable job/work-item outbox; a missing queue returns false. |
| `enqueueIngestionWork` / `publishIngestionMessage` | Strict `{jobId, workItemId}` only. Transactionally create/reuse the source, coalesce an active job and create its root task. Publish after commit; on failure leave `enqueuedAt` null. Existing active work is returned without another direct publication. |

The outbox pump selects queued tasks with null `enqueuedAt`, oldest first, default 50, and records publication time only after send. It catches failures per task. Enqueue also starts an opportunistic pump of five. The cron calls GET `/api/internal/ingestion/pump` every two minutes; GET delegates to POST, caps requested limit at 200, and also drains the persona-analysis queue (outside this module). It does not recover already-published tasks or ordinary file sends. (`web/lib/ingestion-queue.ts` `pumpIngestionOutbox`, `web/app/api/internal/ingestion/pump/route.ts`, `web/vercel.json`; see [Personas and voice](personas-and-voice.md).)

The Python worker parses a fetch or file message only. An identifier-only message fails validation, stays on SQS and eventually reaches a dead-letter queue if configured. The removed TypeScript connector worker is explicitly described as git history in `ingestion/README.md`; it is not a second current handler. (`ingestion/src/ingestion/worker.py` `parse`, `handle`, `run`.)

For a file the worker:

1. Downloads the signed HTTPS original to a temporary directory. Converts text/Markdown/JSON as text; office documents, CSV and PDF with AnyDoc; audio/video with AssemblyAI speaker labels and language detection; images with OpenRouter vision OCR. It attempts to delete a completed AssemblyAI transcript; deletion errors are tolerated. (`ingestion/src/ingestion/worker.py` `download`, `process`; `converters.py`.)
2. Redacts the title and text blocks before writing Markdown. Long blocks are split at line/sentence boundaries around a 120-word target. A failed PII check fails the file, not an unchecked partial output. The placeholder mapping containing real values is dropped. Original S3 files and DB filename-derived titles are not redacted by this step. (`ingestion/src/ingestion/chef.py`, `vendor/pii_redact.py`; `web/lib/org-knowledge.ts`.)
3. Uses Chonkie Slumber with a word tokenizer, 1,000-word chunk window, Qwen via OpenRouter and two configured chunker retries. Adjacent chunks merge when either is below 150 words and their offsets touch, using exact source slices; merging can exceed the initial window. Embeddings run once on the resulting chunks using `openai/text-embedding-3-small` by default. `CHUNK_MODEL`/`EMBEDDING_MODEL` can override defaults; the query model must match the stored vectors. (`ingestion/src/ingestion/__init__.py`, `refinery.py`.)
4. Only after conversion/redaction/chunking/embedding succeeds, sends `start`, batches of up to 50 chunks, then `complete`. Thus `digesting` does not mean the conversion just began. The worker has SQS access but no direct Postgres/S3/Chroma credentials; file transfers use signed URLs and results use `x-internal-secret`. (`ingestion/src/ingestion/worker.py`.)

The results route validates payloads and confirms the document belongs to both the claimed org and KB. Missing/deleted/mis-scoped documents return 404. Storage errors return 500 for retry. (`web/app/api/internal/ingestion/results/route.ts`.)

| Result | Web-side effect |
| --- | --- |
| `fetched` | Set original size, `queued`, clear error; send file-processing message. |
| `start` | Provision org Chroma DB, clear previous S3 chunk files, set `digesting`, clear error. It does not clear Chroma chunks. |
| `chunks` | Upsert supplied vectors without re-embedding, using deterministic IDs; write `part-NNNN.jsonl`. |
| `complete` | Save redacted Markdown, delete Chroma chunks whose index is at least the new chunk count, set `indexed`/`indexedAt`/Markdown key and clear error. |
| `failed` | Record error. Only `final: true` changes status to `failed`. |

The effects above are from the results route and `MainCollectionService.upsertKnowledgeChunks` / `pruneKnowledgeChunks` in `web/lib/main-collection.ts`. No job counters or source-sync timestamps are updated by this route.

The worker polls one message at a time with a 300-second visibility timeout, extends visibility every 150 seconds and finishes its current item on termination. Success or a results 404 deletes the message. Other failures report `failed`, leave the message for retry, and mark it final at `INGESTION_MAX_RECEIVE_COUNT` (default five). Operators must configure SQS redrive to match; code does not create the queue/DLQ. Invalid messages cannot report a document failure. Signed URL queries are stripped from logged/reported errors. (`ingestion/src/ingestion/worker.py`.)

### Chroma and search

- `ChromaTenantService` provisions database `org_<immutable org ID with non-alphanumeric/underscore/hyphen characters replaced by underscores>` in `CHROMA_TENANT` (default `default_tenant`). It records this on the organization and corrects mismatched stored database settings on uncached lookup. Concurrent creation is handled by retrying lookup. `CHROMA_URL` wins over cloud credentials; otherwise use cloud with `CHROMA_API_KEY`, or localhost:8000. Clients and collection handles are cached per org. (`web/lib/chroma-tenant.ts`, `shared/interview-question.ts` `interviewQuestionOrgDatabaseName`.)
- Every org's `main` collection uses cosine distance and HNSW construction/search settings 200/200 with 24 max neighbors. Knowledge, persona records and scenario items share this collection but have separate `type` filters. Knowledge bases are metadata scopes, not separate current physical collections. (`web/lib/main-collection.ts` `getCollection`, `searchKnowledge`.)
- Direct org search embeds the query, searches `type: knowledge`, returns up to 20 hits and scores each as `1 - distance`. Optional service-level KB/topic filters narrow it. It does not apply the 0.35 relevance cutoff or a DB document-status filter. Knowledge searches run on a process-wide single lane; a `Failed to connect` error clears collection handles and retries once. (`web/app/api/knowledge/search/route.ts`, `web/lib/main-collection.ts` `searchKnowledge`, `runOnChromaLane`.)
- `web/lib/knowledge.ts` `searchKnowledge` resolves the KB's org and uses that org's main collection. It retries without topic hints only when topic-filtered results are empty. With `RERANK_ENABLED=1`, over-fetch at least 20 / four times the requested count, call the AI Gateway reranker (default `cohere/rerank-v3.5`), then keep scores at least 0.35. Reranking failure falls back to original order. Without reranking, the same relevance threshold applies to cosine scores. An empty org search returns empty; it does not fall back to legacy collections.
- Only the no-org legacy `searchCollection` path combines vector top-50 and BM25 top-50 using reciprocal-rank fusion, optionally reranking. It fetches the whole collection for lexical scoring. `ingestDoc` still dual-writes org main and legacy `kb_<KB ID>` collections, tolerating legacy-write failure; worker results write main only. The older TypeScript `chunkMarkdown` groups paragraphs/headings around a 1,200-character target and hard-splits long paragraphs at a 2,000-character cap; it is not the Python topic chunker. (`web/lib/knowledge.ts`.)
- Web query embeddings use batches of 100, the configurable AI Gateway/OpenRouter-compatible endpoint and a 120-second request timeout. A configured OpenRouter alternate is tried after non-success HTTP responses; a thrown fetch error exits rather than reaching that fallback. (`web/lib/knowledge.ts` `embedTexts`.)

### Which agents read which knowledge

| Consumer | Scope and boundary |
| --- | --- |
| Compiled web runtime | `getAgentConfigForAgent` prefers `Agent.data.knowledgeBase`, else `knowledge_bases`; when neither selects bases, it includes every org KB with an indexed document. The compiler requires KBs and approved topics for technical interviews. Runtime retrieval uses these approved bases and optional phase topics; lookup can remain off for non-domain turns. (`web/lib/specs.ts` `getAgentConfigForAgent`, `web/lib/runtime/compiler.ts`, `web/lib/runtime/openai.ts` `shouldRetrieveKnowledge`, `retrieveKnowledge`.) |
| Eve interview/chat tools | `search_knowledge` and project-knowledge prefetch explicitly request `acme-knowledge` within the current org. `buildSessionContext` advertises that same slug only if it has an indexed document. This is not the configured-base selection above. Studio search requires an indexed document in that KB and returns relevance/attribution. (`chat/agent/tools/search_knowledge.ts`, `chat/agent/lib/project-knowledge.ts`, `web/lib/session-context.ts`, `web/app/api/copilot/studio/route.ts`.) |
| Full knowledge read | `read_knowledge_document` reads an org-scoped, indexed document with a Markdown key, 12,000 characters per page. Default page 1; requests past the end clamp to the final page (input page maximum 500). It checks org/document status, not attachment to the session's configured KBs. (`chat/agent/tools/read_knowledge_document.ts`, `web/app/api/copilot/studio/route.ts`.) |
| Client role play | Both knowledge tools return disabled through `roleplayGuard` in `roleplay-client` mode. This guard does not block interview role plays or twins. (`chat/agent/lib/session-mode-lookup.ts`, `chat/agent/lib/session-mode.ts`, both knowledge tool files.) |
| Twin / skill twin | Generated skill text and `scenario_item` examples are separate from raw `type: knowledge` chunks. Example search is scoped to the twin's skills/versions; removing a raw document does not delete generated skill items. The knowledge tools' current guard does not enforce the plan's proposed twin ban. (`web/lib/main-collection.ts` `searchScenarioItems`, `web/app/api/copilot/studio/route.ts`, `web/lib/org-knowledge.ts` `deleteDocument`; see [Twins](twins.md).) |
| Copilot source reader | All org documents with non-null Markdown key and status other than `failed`, oldest first, regardless of `indexed` status. Returns 15-minute links plus a version hash of IDs/update times; `versionOnly=1` returns version/count. Source deletion removes it from later listings but not skills already built from it. (`web/app/api/internal/knowledge-sources/route.ts`; see [Copilot](copilot.md).) |
| Persona style | Separate `persona_voice` / episode/style record types, not knowledge-document chunks. Knowledge's Markdown chunker explicitly excludes persona voice. (`web/lib/knowledge.ts` `chunkMarkdown`, `web/lib/main-collection.ts`; see [Personas and voice](personas-and-voice.md).) |

### Delete and retry

- Document delete first checks org ownership. For source-backed documents it fails all active jobs/tasks for that source. It removes knowledge vectors (except a never-indexed, source-less new-format upload), legacy per-document S3 directory, current original directory and worker-output directory, then hard-deletes the row. S3 failure prevents the final row delete; Chroma removal catches errors internally. It leaves the source row and generated skills/items alone. (`web/lib/org-knowledge.ts` `deleteDocument`, `web/lib/main-collection.ts` `removeKnowledgeDoc`.)
- Source delete marks active tasks/jobs failed, clears job active keys and sets finish time, removes each document's knowledge vectors and **only its `kbPrefix` S3 artifacts**, then deletes documents/source. S3 cleanup errors are logged and ignored. Connection delete calls this for dependent sources and deletes the connection credentials. It makes no external OAuth-revocation call. (`web/lib/connectors.ts` `deleteSource`, `deleteConnection`.)
- The older base/file delete removes legacy S3 prefixes, org knowledge vectors and legacy collections/doc chunks before deleting DB records. It does not enumerate current `knowledge/files` or `ingest/files` directories. KB deletion cascades its sources/documents/jobs in Postgres. (`web/lib/specs.ts` `deleteKnowledge`, `removeEmbeddings`; `web/lib/knowledge.ts` `removeCollection`, `removeDoc`; schema.)
- Reindex by document ID requires a stored, non-`pending` original and a configured file queue. It sends the original through conversion/redaction/chunking/embedding again, then sets `queued` and clears the error. It is not source refresh and does not fetch changes from Drive/Notion/YouTube. There is no coalescing or run ID on these file messages. (`web/lib/org-knowledge.ts` `reindexDocument`, `web/lib/ingestion-queue.ts` `queueKnowledgeFile`.)

## Rules

1. Current upload/import/reindex/delete/source-management/OAuth mutations require admin or team; missing that guard gives 401. Direct read routes and older catch-all mutations require only a signed-in enabled org membership. Test those surfaces separately, not as one blanket studio-only rule. (`web/lib/org.ts`; route guards listed in Entry points.)
2. A KB slug must start with an ASCII letter/digit and contain only letters/digits/dot/underscore/hyphen. Existing `(orgId, slug)` creation is reused; documents have unique KB-local slugs. (`web/lib/specs.ts` `validSlug`, `createKnowledgeBase`; schema.)
3. Current upload rejects zero bytes, more than `25 * 1024 * 1024` bytes by default, or an extension outside `KNOWLEDGE_UPLOAD_EXTENSIONS`, before document creation. It validates extension, not file signatures. Missing multipart file is 400; thrown validation/storage errors from this route are 500. (`web/lib/org-knowledge.ts`, `web/lib/documents.ts`, `web/app/api/knowledge/upload/route.ts`.)
4. A public Notion import must not include `connectionId`; an OAuth import must include one belonging to the org. An accepted queue response does not prove a crawl ran. (`web/lib/notion.ts`, `web/lib/notion-ingestion.ts`, worker `parse`.)
5. YouTube import requires an active org connection and a video owned by its channel; private videos fail before storage. Refresh reuses the source/document, whereas an indexed non-refresh import returns that document. (`web/lib/youtube-ingestion.ts`, `shared/youtube/client.server.ts`.)
6. Drive import trusts only a validated file ID, server-read Google metadata and this org/user's unexpired token cookie. Mutation origin mismatch is 403; expired authorization is 401. No permanent connection or background Drive refresh is created. (`web/lib/google-drive.ts`, Drive import/session routes.)
7. Old-style source jobs coalesce while queued/running; `(jobId, workKey)` is unique. Ordinary file reindexes do not share that guarantee. (`web/lib/ingestion-queue.ts`, schema and active-source migration.)
8. Worker result payloads require the internal secret on Vercel and a matching document/org/KB. Unauthorized is 401, invalid schema is 400, missing/mis-scoped document is 404, storage failure is 500. (`web/app/api/internal/ingestion/results/route.ts`.)
9. Retrying a chunk batch overwrites the same `kb_<docId>#<index>` IDs; completion prunes indices at or above the new count. It does not atomically swap the document's complete index. (`web/lib/main-collection.ts`, results route.)
10. Org search always filters `type: knowledge`; a KB-scoped search additionally filters `kbId`. The user-facing org search has no relevance cutoff; `knowledge.ts` KB search excludes scores below 0.35. (`web/lib/main-collection.ts`, `web/lib/knowledge.ts`, both search routes.)
11. Document preview must resolve the original through the caller's org and returns null/404 for missing or `pending` originals. URLs default to one hour. Chunk inspection filters doc ID inside the org DB, sorts by chunk index and returns at most 300 records; it does not first verify a DB document row. (`web/lib/org-knowledge.ts` `getPreviewUrl`, `getDocumentChunks`; `web/lib/s3.ts` `presignedGetUrl`; document preview/chunks routes.)
12. Source deletion and disconnect are destructive locally, including dependent documents; they do not delete the external provider's original. Raw-document deletion does not remove generated scenario/skill examples. (`web/lib/connectors.ts`, `web/lib/org-knowledge.ts`, `web/lib/main-collection.ts` deletion filters.)

## Edge cases and limits

- **Accepted current upload extensions:** `doc docx docm ppt pps pot pptx pptm ppsx ppsm xls xlsx xlsm xlsb odt ods odp rtf epub pdf csv md markdown txt json mp3 m4a wav aac ogg flac mp4 mov webm mkv png jpg jpeg webp`. Older synchronous uploads and Drive use the smaller `ALL_DOCUMENT_EXTENSIONS`: office/document list plus `md txt json csv`, not audio/video/images or `.markdown`. (`web/lib/documents.ts`, `web/lib/google-drive.ts`.)
- **HTTP versus service size:** upload/Drive service limit is 25 MiB; Drive handles Google's 10 MB Workspace-export limit with a specific 413 error. Ordinary KB uploads still send multipart through a web function, not direct browser-to-S3 upload. The 4.5 MB Vercel request cap documented in `plans/uploads-to-s3.md` can therefore prevent a nominally permitted large knowledge upload before service validation. (`web/app/api/knowledge/upload/route.ts`, `web/components/knowledge/knowledge-add-source-dialog.tsx`, `web/lib/google-drive.ts`.)
- **Worker limits:** original download/video maximum 2,000,000,000 bytes; downloaded video is size-checked after yt-dlp finishes, with a one-hour download timeout. Converted Markdown maximum 3,500,000 UTF-8 bytes. Results schema independently accepts Markdown up to 4,000,000 characters, at most 100 chunks per batch, chunk text up to 200,000 characters and vectors of 1–4096 numbers; it does not verify model/dimension equality or contiguous indices. (`ingestion/src/ingestion/{worker,fetch}.py`, results route.)
- **Preview is the original:** worker redaction does not sanitize originals, filenames or DB titles. Org members who can call preview receive access to those originals. (`web/lib/org-knowledge.ts` `uploadDocument`, `getPreviewUrl`; `ingestion/src/ingestion/chef.py`.)
- **No atomic reindex snapshot:** batches become searchable before completion; old high-index chunks remain until completion. A failed run may leave partial/new/old vectors and a previous Markdown key. Results carry no attempt/run generation, so overlapping reindexes are not ordered or fenced. (`web/lib/main-collection.ts` `upsertKnowledgeChunks`, `pruneKnowledgeChunks`; results route; `reindexDocument`.)
- **Deletion races:** a later callback normally gets 404 after row deletion, but the results route's initial lookup and storage writes are not one transaction with deletion. The never-indexed-upload optimization can skip removing partial vectors from a failed first run. Chroma removal errors are swallowed. (`web/lib/org-knowledge.ts` `deleteDocument`, results route, `web/lib/main-collection.ts` `removeKnowledgeDoc`.)
- **Duplicate sends/imports:** file messages have no deduplication; a retried `fetched` callback can enqueue processing again. Drive reuses only `uploaded` snapshots, so queued/indexed snapshots can be imported again. Concurrent same-name uploads can race the pre-insert slug check against the unique constraint. (`web/lib/ingestion-queue.ts`, results route, Drive import route, `web/lib/org-knowledge.ts`.)
- **Operational shortcuts:** client/collection maps are unbounded per active org; org DB validation is skipped after a client-cache hit. Legacy BM25 reads all texts per query (comment says suitable below roughly 10k chunks). Reranking is off by default to avoid voice latency. (`web/lib/chroma-tenant.ts`, `web/lib/main-collection.ts`, `web/lib/knowledge.ts` shortcut/ponytail comments.)
- **Stats are not a durable chunk ledger:** total bytes/docs come from Postgres; knowledge/persona counts page Chroma. Chroma failures log a warning and leave counts zero. Only `persona_voice` counts as persona moments, not episode/style types or scenario items. (`web/lib/org-knowledge.ts` `getStats`.)
- **Secrets and local mode:** results require `INTERNAL_API_SECRET`; pump uses `CRON_SECRET || INTERNAL_API_SECRET` as Bearer or `x-internal-secret`. If absent, both fail closed on Vercel but allow local off-Vercel calls. (`web/app/api/internal/ingestion/{results,pump}/route.ts`.)
