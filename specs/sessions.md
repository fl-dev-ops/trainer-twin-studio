# Sessions

> A session is one practice conversation, not the user's sign-in session. This module starts the conversation, connects the browser to LiveKit, saves its ending and evidence, records time used, and starts the right report. It also exposes the session-bound runtime and workspace routes. The main owners are `web/lib/interview-sessions.ts`, `web/lib/session-activation.ts`, and `web/lib/session-lifecycle.ts`.

## Who uses it

- **Learner:** starts or resumes their own voice practice, attaches allowed documents, ends the call, and leaves feedback. Routes resolve the signed-in user and organization through `web/lib/session-user.ts` `resolveSessionUser`; ownership checks live in `web/app/api/sessions/*`.
- **Org admin and team:** try agents using org credits for billed voice calls (free when unbilled; studio chat unmetered), list org sessions, and read learners' snapshots and recordings. See [Organizations and roles](orgs-and-roles.md). Pointers: `web/lib/interview-sessions.ts` `activateSession`, `web/app/api/sessions/route.ts` GET, `web/app/api/sessions/[id]/route.ts` GET.
- **Voice agent and session browser:** currently both receive/use a session-scoped runtime token for runtime, command, UI-state, and recording-upload routes. The voice agent uses a separate shared service secret for the completion webhook. Pointers: `web/lib/interview-sessions.ts` `authorizeRuntimeSession`, `web/app/api/sessions/webhook/route.ts` `authorized`.
- **API integrator:** reads role-play session results through the public API; this is not the runtime-token API. See [Public API](public-api.md); `web/app/api/v1/sessions/route.ts`.

[Practice](practice.md) is the rule spec for twin calls; [People](people.md) supplies membership and refusal rules. Role-play access/resume is still a separate branch, not a complete practice-rule implementation. Remaining differences are under Mismatches.

## Data

### Session record

`web/prisma/schema.prisma` `InterviewSession` owns these fields. Statuses are strings, not a Prisma enum.

| Fields | Meaning / writer |
| --- | --- |
| `id`, `orgId`, `userId`, `agentId` | Call identity, org and owner; activation writes them. |
| `shareCode`, `activationKey` | Unique call code and nullable unique activation key; activation writes them. |
| `deploymentId`, `assignmentId`, `twinAssignmentId`, `mode` | Launch/access links; `mode` defaults to `voice`, also supports `chat`. |
| `personaSlug`, `personaVersion`, `agentSlug`, `agentVersion`, `compiledSnapshot` | Start-time configuration references and compiled data; activation writes them. |
| `contextId`, `contextName` | Legacy primary document; additional documents use the join table. |
| `status`, `createdAt`, `startedAt`, `endedAt`, `deletedAt`, `attempt` | Lifecycle, soft deletion and attempt metadata; `attempt` defaults to 1. Normal activation creates a new row, not an incremented attempt. |
| `runtimeTokenHash`, `runtimeState`, `runtimeRevision`, `lastCompletion`, `warmOpening` | Runtime authorization, progress, latest completion replay, and best-effort opening preparation. |
| `allowedSeconds`, `chargesOrg` | Nullable start-time learner or billed-studio allowance; usage is capped at it. `chargesOrg` selects staff `org_usage`, not learner `usage`. Live billed studio calls hold the whole allowance (`web/lib/org-credits.ts` `runningSeconds`). |
| `livekitRoom`, `livekitDispatchId`, `videoEgressId`, `audioEgressId` | Transport/recording references. Current web activation writes room, dispatch and video egress, not audio egress. |
| `transcript`, `evidence`, `s3AudioKey` | Conversation lines, accumulated evidence, and dedicated audio location. |
| `report`, `reportStatus`, `reportWorkflowRunId` | Stored report JSON, processing status, and durable workflow ID where used. |
| `feedbackRating`, `feedbackNote` | Owner's latest rating and note. |

Writers: `web/lib/interview-sessions.ts`, `web/lib/session-activation.ts`, `web/lib/runtime/openai.ts`, `web/lib/session-warm.ts`, `web/app/api/sessions/webhook/route.ts`, `web/app/api/sessions/recording/route.ts`, and the report/feedback owners below.

`InterviewSessionDocument` has composite key `(sessionId, documentId)` and a creation time. Activation and the documents route add links; deleting either parent cascades links. `WorkspaceCommand` has globally unique `id` (the tool call ID), `sessionId`, `tool`, `input`, `status`, `result`, and completion timestamps. Its lifecycle is `pending → completed | failed`. Pointers: `web/prisma/schema.prisma`, `web/lib/workspace-commands.ts`.

A session cannot have both assignment kinds (`session_one_assignment_kind`); twin sessions must be voice. DB access checks are also enforced by triggers in `web/prisma/migrations/20261027020000_twin_access/migration.sql`.

### Lifecycles

| State / transition | What actually writes or accepts it |
| --- | --- |
| `assigned` | Schema default and legacy `createAssignedSession`; ordinary activation creates a separate `activating` row. The legacy helper is retained for local scripts, not assignment starts (`web/lib/interview-sessions.ts`). |
| new → `activating` → `active` | Create snapshot/state, initialize chat, then stamp `startedAt` and token hash (`activateSession`). |
| `activating` / `active` → `failed` | Chat initialization or later LiveKit activation failure (`activateSession`, `web/lib/session-activation.ts`). |
| → `completed` / `abandoned` | Shared finalizer on explicit ending, replacement, disable or stale sweep; status and usage commit together. `completed` cannot be downgraded; `abandoned` can later become `completed` (`finalizeSessionRow`, `resolveSessionEndStatus`, `sweepStaleCalls`). |
| `closing` | Accepted by runtime authorization, but these lifecycle functions do not set it (`authorizeRuntimeSession`). |
| `assigned` → `revoked` | Member disabling; open `activating`/`active` calls instead close as `abandoned` (`web/lib/members.ts` `setMemberDisabled`). |
| failed row → deleted → new activation | A retry with the same activation key deletes the failed row first (`activateSession`). |

Report lifecycle is independent: `none`/null/`failed → generating → completed | failed`. A failed report does not make the call status `failed`. Pointers: `web/lib/session-close.ts`, `web/workflows/steps/session-end.ts`, `web/lib/report-model.ts`.

## How it works

### 1. Activate or resume

1. `POST /api/sessions` resolves user and org. Either missing gives `signed_out`/401/“Sign in first.” The body must name a share code, agent slug or deployment key; a missing selector gives `invalid_input`/400. Without a share code it calls `practicePerson`; slug-only starts additionally require studio role (`studio_only`/403). Only literal `mode: "chat"` selects chat; all other values select voice. Only literal `calibrate: true` requests calibration; it forwards that flag and one `contextId`, not `contextIds`. (`web/app/api/sessions/route.ts:21–50`; `web/lib/session-user.ts` `resolveSessionUser`.)
2. `activateSession` first calls `practicePerson`: database member lookup, `no_org`/403 if absent, `member_disabled`/403 if disabled. With `calibrate: true`, a non-studio member is refused `studio_only`/403/“Only the organization's admin and team can do this.” before any twin access lookup; a studio non-twin calibration is `not_found`/404/“Not found.” (`web/lib/interview-sessions.ts:232–236,311–312`.) For role-play codes it checks account ownership, pending/used status, active deployment and requested mode, but not `expiresAt`. For twin codes it uses `twinAccessByCode(join: false)`: no member/assignment creation; existing learners need usable access; common codes allow studio without assignment. Another-org or archived twin code is `not_found`/404; unknown codes return null. Direct twin starts allow studio or an assigned learner in the service (the HTTP slug-only guard is narrower). Access checks are separate from the shared person/allowance helpers. (`web/lib/interview-sessions.ts:230–309`; `web/lib/twin-access.ts` `twinAccessByCode`, `twinAccessByAgent`; see [Twins](twins.md), [Role plays](roleplays.md).)
3. Choose the activation key. Every twin start, by personal/common code, slug or deployment, uses a fresh `twin:<random>` key and ignores caller idempotencyKey: **twins never resume**. A role-play assignment reuses the latest live call's key for that assignment/user, else `assignment:<id>:<random>`; it ignores the supplied key. A direct role-play agent/deployment uses `deployment:<deploymentId>:<idempotencyKey>`, else `direct:<random>`. `ensureDeployment` may write before later validation. Twins refuse chat with voice_only/400/“Twin calls are voice only.” Learner role-play chat still uses MinutesError/400/minutes. (`web/lib/interview-sessions.ts:259–309`; `web/lib/deployments.ts` `ensureDeployment`.)
4. A matching role-play activating/active row resumes: refresh token hash and return stored mode/status and `max(0, allowedSeconds - floor(elapsed))`, from startedAt or createdAt. Resume precedes pause/minimum/snapshot/locked rechecks. A matching failed row is deleted; another ended key returns null (and can mark a pending role-play assignment used). Ordinary role-play links repeat after ending. No twin key is reused in this lookup. (`web/lib/interview-sessions.ts:311–330`.)
5. Load an unarchived same-org agent and ready documents. Unknown/archived agent is `not_found`/404. Missing/wrong-owner context or a file outside the before PDF/image 10 MiB policy is a 400 error without a refusal code. For agents using before settings, supplied documents require `preUpload`; otherwise `invalid_input`/400 says the twin/role play does not take documents. Compile the snapshot, pin main-twin skills by persona, and prepare document links. These reads and access checks are outside the lock. (`web/lib/interview-sessions.ts` `sessionSnapshot`, `activateSession`; `web/lib/session-activation.ts:38–44` `startRefusal`; [Platform](platform.md).)
6. For studio voice, refresh org credits from Meteroid before taking `minutes:<org>`. One transaction then re-reads the person, ends/charges every other activating/active call by that user in this org through `finalizeSessionRow`, calls `startAllowance` on the resulting balance and creates the new activating row and documents. The lock serializes new starts with other starts and grants (15-second max wait/transaction timeout). Pause or short-credit refusal rolls back all those ends/charges and the new call; no replaced room/workflow is touched then. All roles now use this replacement path, not a quiet same-twin studio abandon. With `calibrate: true`, it then creates `TwinCalibration` with this new call's ID and creator equal to its owner, before commit; a calibration insertion failure also rolls back the replaced ends, new call and documents. It rechecks person/allowance, **not** access, live twin or document state or the earlier studio-role decision. (`web/lib/interview-sessions.ts:355–408`; `web/lib/db.ts` `withLock`; `web/lib/minutes.ts` `minutesLock`.)
7. `startAllowance` checks local pause first (`org_paused`/403; Billing's learner/studio message). Learner seconds below 60 give `credits_out`/403; 60–299 give `credits_short`/403 with whole minutes; 300 or more becomes the allowance. Billed studio has the same boundaries with `org_credits_out`/`org_credits_short`; unbilled studio gets null allowance and `chargesOrg: false`. All billed live studio allowances are held in org balance, even before startedAt. Studio chat bypasses this helper and remains unmetered/unpaused. Resume also bypasses it. (`web/lib/practice.ts:22–63`; `web/lib/org-credits.ts` `runningSeconds`; see [Credits](credits.md), [Billing](billing.md).)
8. After commit, schedule replaced studio usage and start each replaced call's end workflow (only rows with endedNow). Derive the new runtime token and initialize chat with POST <CHAT_URL>/internal/sessions, shared-secret bearer, org header, `{sessionId,mode,contextVersion:1}` (default host http://localhost:2000). Success transactionally changes **only status=activating** to active/start time/token hash; only the winner marks its role-play assignment used. If another start/disable/sweep already ended the row, give call_replaced/409/“This call was replaced by one you started elsewhere.” and do not make it live. Chat failure marks failed/end time/no token only if still activating; replaced/ended rows keep their end, and replaced older calls stay ended. Missing secret before the try still leaves activating. (`web/lib/interview-sessions.ts:399–428` `activateSession`, `initializeChatSession`; `web/lib/practice.ts:31` `callReplaced`.)
9. The route awaits `runSessionStart`: start-session workflow, open then voice connect, both zero retries; chat returns runtimeToken as conversationToken. Only failure to start the workflow falls back inline, not failure of a running workflow. `startRefusal` preserves AppError code/status/message; selected context/deployment errors still have no code; null activation becomes 403 “Invalid or already used session URL” without code. Success returns `{session, participantToken?, room?, conversationToken?}`, **including session.runtimeToken in voice responses**. New sessions carry `session.calibrationId` (ID for a calibration, null otherwise); the start workflow returns it unchanged, so the browser does not mark the call later. Calibration setup failure after commit keeps the calibration attached to the failed/ended call; it is not rolled back with remote setup. (`web/lib/interview-sessions.ts:398–439`; `web/lib/session-activation.ts:63–67` `startSessionNow`; see [Twins](twins.md#calibrate-and-save-results).) It schedules best-effort opening warmup with Next `after()`. Unexpected failures are generic 500. (`web/lib/run-session-start.ts`; `web/lib/session-activation.ts`; `web/workflows/start-session.ts`, `web/workflows/steps/start-session.ts`; `web/app/api/sessions/route.ts:50–57`.)

### 2. Connect LiveKit and release the greeting

1. Resolve a ready voice: explicit agent voice first, otherwise persona voice; accept only same-org/global voices. If unavailable, try the alphabetically first ready global voice (`web/lib/session-activation.ts` `connectVoice`). See [Personas and voice](personas-and-voice.md).
2. Room name is the session ID. Create it with empty timeout 600 seconds and departure timeout 30 seconds, or update existing room metadata. Reuse a dispatch for the configured agent name, otherwise create one. Metadata contains `sessionId`, `orgId`, `agentSlug`, runtime token, `hold_opening`, optional voice, absolute `ends_at`, and agent kind (`web/lib/livekit.ts` `activateLiveKitSession`).
3. When a bucket exists, reuse an egress in status 0/1/2 or try a room-composite MP4 recording, H264 1080p30, mixed audio plus screen/speaker tiles. Key: `<S3_BASE_PREFIX>/<orgId>/recordings/<sessionId>/video.mp4`; prefix defaults to `trainertwin-dev`. Egress failure only warns. The expected key can be saved even when egress did not start (`web/lib/livekit.ts`).
4. Store room, dispatch, egress ID and video key. Return participant JWT and room. JWT identity is `user-<userId>` and grants room join, publish, subscribe and data publishing (`web/lib/session-activation.ts`, `web/lib/livekit.ts`).
5. Hold the greeting if the agent has an intro video or the caller requests it. `SessionView` starts with `holdOpening: true`; after launch, connection, agent arrival and any intro, it applies mic/camera choices and sends reliable `{ type: "begin-opening" }`. The Python agent buffers typed input and gates audio while held, with a 60-second release timeout. This is not an unbounded pause (`web/components/session-view.tsx`, `agent/src/agent.py` `TrainerAgent`, `OPENING_RELEASE_TIMEOUT`). Runtime behavior belongs to [Voice agent and chat](voice-agent-and-chat.md).

### 3. End the call and save transcript/evidence

- A refused/failed browser start keeps `startedRef` set throughout the five-second get-ready countdown: no repeated POST each tick. Only explicit “Try again” resets it (`web/components/session-view.tsx`).
- The browser derives a deadline from `launch.session.secondsLeft`. A non-manual end at or after 30 seconds before that deadline is `time_up`, finalized as completed. The end card says “Time's up” with learner/trainer or org-credit guidance; learner feedback includes the time-up explanation above the form. Manual endings remain manual even near the deadline (`SessionView` `handleDisconnect`, `TIME_UP_MARGIN_MS`).

- `closeInterviewSession` calls `finalizeInterviewSession`, which runs `finalizeSessionRow(input, tx)`: status, transcript/evidence, first observed end time, token clearing, role-play used state and `writeSessionUsage` commit together. A usage-write failure rolls back the end instead of leaving a saved uncharged row. Meteroid reporting is scheduled after commit. Only the transaction that changed status (`endedNow: true`) calls `startSessionEnd` (TWIN → end-twin-session, otherwise end-roleplay-session). The workflow strictly closes LiveKit and safely retries charge, then scores a twin calibration or claims/generates a report. Startup failure attempts strict close/charge inline, logs failures and generates neither a report nor a calibration score. (`web/lib/interview-sessions.ts:54–131`; `web/lib/session-lifecycle.ts`; `web/lib/session-end.ts`; `web/lib/session-close.ts`.)
- Browser finalization requires the owning user in the same org and status `completed` or `abandoned`. It accepts nonempty transcript arrays, keeping object entries with string `text`; evidence must be a nonempty object. `SessionView` uses keepalive, checks HTTP success, and keeps a visible save/retry error rather than silently ending on failure (`web/app/api/sessions/finalize/route.ts`, `web/components/session-view.tsx` `finalizeSession`, `handleDisconnect`).
- Sequential finalization keeps the first `endedAt`, clears the token hash, and never downgrades completed. Requested abandoned changes only activating/active/closing; requested completed also permits abandoned → completed. Completed/failed/revoked/assigned retain their status/end; same-status retry enriches data but does not clear the token/write usage/start end work again (endedNow=false). A linked pending role-play assignment becomes used on completed/abandoned. Evidence is a shallow merge; incoming keys replace matching old keys (`web/lib/interview-sessions.ts` `finalizeSessionRow`, `mergeSessionEvidence`).
- Normally the first nonempty transcript wins. For report kinds other than legacy `session`, the authenticated agent webhook may replace it with a nonempty full transcript and marks `evidence.transcriptFinal = true`; this includes twin calibrations. Empty incoming transcripts never clear an existing one (`web/lib/session-after.ts` `usesAgentTranscript`, `web/app/api/sessions/webhook/route.ts`, `web/lib/interview-sessions.ts`).
- Agent transcript lines are `{ role: "user" | "trainer", text, spokenAt? }`, where `spokenAt` is epoch milliseconds. They come from voice-session history at shutdown. Report readers classify `role: "user"` or `speaker: "learner"` as learner; other roles are treated as the AI. `transcriptTurns` joins adjacent learner pieces except standalone “Feel(s) off” messages, using the shared `isFeelsOffMessage` predicate (see [Voice agent and chat](voice-agent-and-chat.md)). (`agent/src/agent.py` `on_session_end`, `web/lib/twin/stats.ts:27–29,136`, `web/lib/generate-session-report.ts`).
- Browser finalize also best-effort creates the learner memory collection and asynchronously saves learner lines with key `session_<id>`. Memory/report errors are logged, not returned as save failure. Browser finalize, runtime-token PATCH and recognized-status agent webhook all call closeInterviewSession; no separate processEndedSession dispatcher remains (`web/app/api/sessions/finalize/route.ts`, `web/app/api/sessions/route.ts` PATCH, `web/app/api/sessions/webhook/route.ts`). See [Knowledge](knowledge.md) for memory storage.

### 4. Agent completion webhook

`POST /api/sessions/webhook` is service-secret authenticated, not cookie or runtime-token authenticated. It compares bearer bytes with `COPILOT_SERVICE_SECRET` using equal length and constant-time comparison **before parsing JSON or querying the DB**. Missing secret or credentials returns 401 (`web/app/api/sessions/webhook/route.ts` `authorized`).

| Payload | Accepted behavior (`payloadSchema`, POST in that route) |
| --- | --- |
| `session_id`, `sessionId`, `room_name` | Nullable strings, max 200 each; first truthy value wins, then trim and remove leading `session-`. Find by ID or session share code. Missing identifier: 400; no matching row: 404. |
| `status` | Nullable string, max 40. `COMPLETED → completed`; `FAILED`/`ABANDONED → abandoned`. Other strings or omission perform an evidence/transcript-only update, not a status transition. |
| `transcript` | Nullable array, max 10,000 lines. Each has string `role` ≤40, string `text` ≤50,000, optional nullable nonnegative numeric `spokenAt`; extra line fields are allowed. |
| `report`, `metrics` | Nullable record / optional arbitrary value. `report` fields merge into evidence, not the generated `report` column. Truthy metrics are stored in evidence. |
| `video_url`, `video_s3_key`, `audio_url`, `audio_s3_key`, `participant_identity` | Nullable strings ≤2,000. Media values become evidence fields; participant identity is accepted but not persisted here. |

Malformed JSON/schema returns 400 (up to five validation issues). The handler tries to obtain recording start time from LiveKit egress, ignoring lookup failure. It saves that as epoch milliseconds for report timing. A recognized end status closes the room and finalizes; an unrecognized status calls the finalizer without ending. Same-status/concurrent losing endings enrich saved data but do not start another workflow; abandoned → completed does when it wins its status update (endedNow). No-status webhook never starts an end workflow. Startup failure logs and falls back to close/charge without report; successful webhook response is `{ ok: true, sessionId, status }` (`web/app/api/sessions/webhook/route.ts`, `web/lib/livekit.ts` `recordingStartedAt`).

The producer sends bearer service auth, refuses to send without a configured secret, uses a 15-second request timeout, and retries once after two seconds **only for HTTP 5xx**, not general connection errors or 4xx. Errors are logged rather than propagated (`agent/src/recording/webhook.py` `post_completion_webhook`).

### 5. Usage and recordings

- An end-status finalization that wins the status transition (endedNow) calls `writeSessionUsage(tx, sessionId)` **inside** the end transaction. Usage is whole elapsed seconds, floored, clamped to zero/allowance. Missing row/allowance/end or a currently failed/revoked row writes none; missing start writes a zero-second row for an ended metered call. `createMany(skipDuplicates)` and unique sessionId make retries no-ops. `chargesOrg` chooses `org_usage`, otherwise `usage`; only a newly written positive staff charge asks the caller to report Meteroid usage after commit. `recordSessionUsage` is the standalone idempotent workflow retry. Transcript-only finalizer updates do not charge. Learner live calls count capped elapsed time; studio live calls hold their whole allowance. (`web/lib/interview-sessions.ts:54–56,121–130`; `web/lib/minutes.ts:224–251`; [Credits](credits.md).)
- Provider/model usage is separate from learner seconds. Web runtime meters one turn's accumulated usage by request hash; reports meter model generations; the voice agent flushes usage on shutdown. See [Platform](platform.md) and [Voice agent and chat](voice-agent-and-chat.md). Pointers: `web/lib/runtime/openai.ts`, `web/lib/report-model.ts`, `web/lib/generate-session-report.ts`, `agent/src/agent.py` `on_session_end`.
- Current web activation records composite video with audio. The Python `recording/egress.py` contains separate audio/video helpers, but current `agent/src/agent.py` does not call them. Do not assume every session gets a separate audio file (`web/lib/livekit.ts`, `agent/src/recording/egress.py`).
- `POST /api/sessions/recording?sessionId=...` accepts nonempty raw bytes under an authorized live runtime token. It requires S3 configuration, writes `audio/wav` at `<orgPrefix>/recordings/<sessionId>.wav`, and saves `s3AudioKey`. It refuses more than `200 * 1024 * 1024` bytes (200 MiB; message says MB) using both declared Content-Length before reading and actual length after `arrayBuffer()`: `recording_too_big`/413/“A recording can be at most 200 MB.” Empty is `invalid_input`/400/“Empty recording”; invalid token is `runtime_token_invalid`/401/“This call is no longer available.” No WAV-content check; an absent/false length header still permits full buffering before the actual-size refusal. (`web/app/api/sessions/recording/route.ts:4–35`; `web/lib/s3.ts` `recordingKey`.)
- Playback routes allow the owner or admin/team in the same org and redirect to a one-hour S3 signed GET. Audio requires `s3AudioKey`; video uses evidence's `videoS3Key` or the expected composite key without checking that an object exists. These routes do not filter `deletedAt` (`web/app/api/sessions/[id]/audio/route.ts`, `web/app/api/sessions/[id]/video/route.ts`).

### 6. Generate and show reports

After the end is saved, `startSessionEnd` chooses the workflow by current Agent.kind. Both run closeRoom (strict retries, exhausted errors ignored) → chargeCall. The twin workflow then checks calibration before takeReport; the roleplay workflow proceeds to takeReport. closeLiveKitSession strict ignores 404/not_found/failed_precondition but propagates other failures; ordinary non-strict callers retain best-effort behavior (`web/lib/session-end.ts`; `web/lib/livekit.ts`; `web/workflows/end-twin-session.ts:19–29`; `web/workflows/end-roleplay-session.ts`; `web/workflows/steps/session-end.ts`).

For a twin calibration, `readCalibration` returns none without a calibration row, ready only for `evidence.transcriptFinal === true`, otherwise waiting. The end workflow waits at most twelve 10-second sleeps, then calls the scoring step and returns `{status: "ended", calibration: "scored"}` without a learner-report claim. Timeout uses the saved provisional transcript, including an empty one. `scoreCalibration` has three retries and calls `scoreCalibrationOnce`: an atomic `scoreClaimedAt` claim on an unscored row (null or older than two minutes), followed by transcript/ratings read, Jev classification and counts/`scoredAt` save. No questions saves raw counts without Jev. Model/save failure clears the claim and throws. Missing, already-scored or recently claimed rows return null; the step ignores that result, so “scored” is a workflow branch label, not proof of a saved score. Full count/rating rules belong to [Twins](twins.md#calibrate-and-save-results). (`web/workflows/end-twin-session.ts:22–26`; `web/workflows/steps/calibration.ts:9–22`; `web/lib/twin/calibration-score.ts:71–103`.)

reportFor reads current after.report through reportKindOf: explicit twin/roleplay, otherwise twin for TWIN or session for v1. Calibrations are excluded on the twin path. ### 7. Documents, commands, UI state and web completions

- **Attach a document:** owner-cookie auth; call must be undeleted and activating/active. Use pinned before settings, falling back to current agent data; require `duringUpload`. Accept only ready same-org documents owned by this user, PDF ≤10 MB or image ≤5 MB. Add the join link idempotently and, if a snapshot exists, append document ID/manifest once. The next runtime turn can read the updated snapshot (`web/app/api/sessions/[id]/documents/route.ts`). File creation/expiry is [Platform](platform.md), not this route.
- **Run a command:** studio enqueues by tool call ID only for activating/active sessions in its org; upsert never changes an existing command. Browser polls pending commands oldest first and acknowledges result or failure using the runtime token. Only pending commands can be completed, so duplicate acknowledgments do not rewrite results. Enqueue waits up to 60 × 500 ms; other commands time out as pending, but `finish_session` closes as completed even on timeout. This close uses closeInterviewSession and therefore starts the end workflow on status change (`web/lib/workspace-commands.ts`, `web/app/api/sessions/[id]/commands/route.ts`, `web/app/api/sessions/[id]/commands/[callId]/route.ts`). Tool availability belongs to [Voice agent and chat](voice-agent-and-chat.md).
- **Report UI state:** runtime-token POST stores `{ active, key, updatedAt }` under `runtimeState.uiState`. Allowed surfaces are code, canvas, pdf, image, presentation; anything else becomes null. Key is truncated to 120 characters. Invalid/non-object body is 400. GET returns that state or null; it does not execute an action (`web/app/api/sessions/[id]/ui-state/route.ts`).
- **Web completions:** `POST /api/v1/chat/completions` delegates to `handleCompletions`. It uses a runtime bearer token, not an external API key; missing/invalid token gives OpenAI-shaped 401. Bad JSON gives 400. This is the web deterministic runtime adapter, separate from the chat-service initialization above (`web/app/api/v1/chat/completions/route.ts`, `web/lib/runtime/openai.ts`).
- The web adapter defaults `messages=[]`, `stream=true`, `tools=[]`; compiles the pinned snapshot (loads one if absent), updates runtime/evidence/transcript, and increments revision. It caches **only the latest** completion by normalized messages plus token hash/session ID. Repeating that hash returns cached JSON or SSE with `X-Idempotent-Replay: true`, without another grading pass. New responses expose `X-Execution-Count`; SSE ends with `[DONE]` and includes usage. This is buffered SSE, not token-by-token provider streaming (`web/lib/runtime/openai.ts` `runCompletionPipeline`, `computeRequestHash`, `buildSseStream`).
- Missing specs return 500. Pipeline exceptions become generic OpenAI-shaped 500, not raw exception details; individual direction/analysis/retrieval stages also have fallback paths. This error wrapper begins after authorization and JSON parsing (`web/lib/runtime/openai.ts` `handleCompletions`, `runDirectionCheck`, `runAnalyzerLLM`).

## Rules

1. Activation never creates an org member or twin assignment; twin codes use join=false and a nonmember direct common-code start is refused. Page opening owns common-link joining (`web/lib/pages/learner.ts` `loadSharedSession`; `web/lib/twin-access.ts` `twinAccessByCode`). Every activateSession path rejects absent/disabled membership in its initial check; new creation repeats that check under the lock. Post-check/setup races remain below. Billed admin/team voice calls require at least 5 org credits and set chargesOrg/allowedSeconds; staff chat and unbilled staff voice remain unmetered. Learners require at least 5 personal minutes for a new voice call (`web/lib/interview-sessions.ts` `activateSession`).
2. Twins and metered learners cannot start chat. Twin starts use fresh random keys and never resume, even with a caller idempotencyKey (`web/lib/interview-sessions.ts:260–261,302–309`). A role-play assignment must also allow the requested mode (`activateSession`).
3. A role-play assignment in used status remains usable; a live call resumes, an ended call starts a new practice. Expiry timestamp alone is not an activation refusal (`activateSession`; `web/tests/lib/assigned-activation.test.ts`).
4. Resuming cannot reset `startedAt` or replenish `allowedSeconds`; it returns remaining time, even zero, and is not refused because the org is paused. New voice calls are refused while paused with 403 and the learner/studio message above, using only the app's pause flag (`web/lib/interview-sessions.ts` `activateSession`; `web/lib/billing/paused.ts` `pausedReason`; [Billing code](billing-code.md)).
5. A new call by any role ends the user's other activating/active calls, writes their usage and checks allowance under `minutes:<org>` in one transaction; refusal rolls it all back. Runtime setup is after commit, so this is serialized creation, not a database one-live-call constraint or protection against later resurrection (`web/lib/interview-sessions.ts:352–428`; `web/prisma/schema.prisma`).
6. Runtime authorization accepts only hashes on activating/active/closing rows. Finalization clears the hash, so commands, completions and raw-recording upload cannot use it afterward (`authorizeRuntimeSession`, `finalizeSessionRow`).
7. Webhook auth runs before parsing and mutation; browser cookies and runtime tokens do not substitute for its service secret (`web/app/api/sessions/webhook/route.ts`).
8. Only live rows (plus abandoned → completed) can transition; completed, failed, revoked and assigned keep their status/end. endedNow gates token clearing, usage and dispatch; duplicate same-target ends start end work once. Transcript/evidence may still be enriched. Sequential retries retain the first end time; evidence merges shallowly (`web/lib/interview-sessions.ts` `finalizeSessionRow`).
9. Nonempty final agent transcripts replace browser transcripts only when `usesAgentTranscript` is true. Legacy session-report calls retain their first nonempty transcript (`web/lib/session-after.ts`, `web/app/api/sessions/webhook/route.ts`).
10. Usage is capped at the original allowance and inserted once per session **in the transaction that ends it**. Currently failed/revoked rows get no ledger row; an ended metered call with no start gets a zero row. Post-commit Meteroid reporting and workflow `recordSessionUsage` retries cannot debit twice (`web/lib/interview-sessions.ts` `finalizeSessionRow`; `web/lib/minutes.ts` `writeSessionUsage`, `recordSessionUsage`; see [Credits](credits.md)).
11. End workflows atomically claim completed/abandoned rows with null/none/failed report status; generating/completed claims lose. Report eligibility narrows abandoned to twin learner speech; reportWorkflowRunId is the claiming end run. Twin calibrations bypass that claim and use their own scoring claim/three-retry step after final-transcript readiness or its wait, for both completed and abandoned ends. (`web/lib/session-close.ts`; `web/workflows/steps/session-end.ts`; `web/workflows/end-twin-session.ts:22–29`; `web/workflows/steps/calibration.ts`.)
12. Feedback is owner-only on completed/abandoned calls. Strict body: integer rating 1–5, required trimmed note ≤500 characters, no extra fields. Empty note stores null; repeat submission overwrites the two fields (`web/app/api/sessions/[id]/feedback/route.ts`).
13. Document attachment must pass both ownership and pinned permission checks; a hidden UI control alone is not authorization (`web/app/api/sessions/[id]/documents/route.ts`).
14. A command acknowledgment cannot change a completed/failed command; unknown/already-acknowledged IDs still get `{ ok: true }` from the route (`web/lib/workspace-commands.ts` `completeWorkspaceCommand`, acknowledgment route).
15. Sweep runs every five minutes, selecting at most 200 live rows: activating older than ten minutes, active with startedAt past allowance + two minutes or three hours without allowance. It uses the abandoned end/usage path and continues after per-call failure (`web/lib/session-lifecycle.ts:39–54`; `web/vercel.json:19–20`).

## Edge cases and limits

- End/usage now commit together; workflow startup remains separate and has no durable end-work outbox. Same-status retry does not start an end run. Startup fallback makes no report. An abandoned transition with no learner speech is ineligible when `takeReport` runs; later same-status/no-status transcript enrichment cannot dispatch a new report. Late transcript after a completed report does not regenerate it (`web/lib/interview-sessions.ts:54–56,121–130`; `web/lib/session-lifecycle.ts:23`; `web/lib/session-close.ts` `reportFor`; `web/app/api/sessions/webhook/route.ts`).

- **Activation failure:** chat-init failure marks failed only while the row is still activating; an already-ended row keeps its end. It never revives a replaced call. LiveKit activation failure attempts cleanup using the previously read room references, marks the row failed unless already completed/abandoned, and reverts its role-play assignment from used to pending only if no other started nonfailed call exists. It rethrows; the HTTP route exposes only selected validation messages and otherwise a generic 500. Fresh room resources created before a failure may not yet be stored for cleanup (`web/lib/interview-sessions.ts`, `web/lib/session-activation.ts`, `web/app/api/sessions/route.ts`).
- **Initial document list:** `SessionView` sends both `contextId` and `contextIds`, but POST forwards only `contextId` and `startSessionNow` has no `contextIds` parameter. The helper `activateSession` supports multiple documents, but this browser activation path only passes the first (`web/components/session-view.tsx`, `web/app/api/sessions/route.ts`, `web/lib/session-activation.ts`, `web/lib/interview-sessions.ts`).
- **Missing service secret:** a new row is created before `runtimeToken()` is called, and that call is outside the chat-initialization catch. A missing secret can therefore leave an activating row instead of marking it failed (`web/lib/interview-sessions.ts` `activateSession`, `runtimeToken`).
- **Other active studio calls:** now end through `finalizeSessionRow` with usage, followed by `startSessionEnd` after commit, across all twins/agents in that org. Chat/LiveKit failure of the replacement does not restore the old call (`web/lib/interview-sessions.ts:355–424`).
- **Stale calls:** the agent still grants about 30 seconds for empty-room reconnect and ends at the allowance. The web sweeper now selects up to 200 rows per run, without ordering: activating with createdAt strictly older than 10 minutes, or active with non-null startedAt strictly past startedAt + allowance + 2 minutes (3 hours if no allowance). It calls the normal abandoned end path sequentially, clearing token and charging up to allowance; per-call failures log and do not stop the rest. It covers role plays/studio too, ignores active rows without startedAt, and selects age before finalization; the finalizer atomically rechecks live status, not the stale age condition. Its ended counter increments only when endedNow is true; a row already ended by another caller is not counted again. Query failures escape the route; per-call failures still produce `ok: true`. (`web/lib/session-lifecycle.ts:27–54`; `web/app/api/internal/sessions/sweep/route.ts:9–14`; `web/vercel.json`; `agent/src/agent.py` `watch_empty_room`, `end_at_deadline`, `on_session_end`.)
- **Calibration retry limits:** there is no calibration score-run ID, scoring status/poll repair, hour-age scan or durable enqueue recovery. A model failure is retried by the scoring step, but exhaustion leaves it unscored; startSessionEnd's enqueue fallback only closes/charges. A model-success/save-failure retry repeats model work. A claim left by a crashed worker can be taken over after two minutes only if another scoring attempt actually runs. Recently claimed rows return null successfully, even when still unscored. Later agent transcripts do not regenerate saved counts. (`web/lib/twin/calibration-score.ts:80–103`; `web/workflows/steps/calibration.ts:18–22`; `web/workflows/end-twin-session.ts:25–26`; `web/lib/session-end.ts:21–27`; `web/prisma/schema.prisma:968–982`.)
- **No report recovery loop:** generating with a missing run ID remains pending. Twin polling only repairs known failed/cancelled runs, not a null lookup or an age timeout; role-play polling does not inspect run status (`web/lib/twin/trpc.ts` `sessionReportState`, `web/lib/roleplay/trpc.ts`).
- **Latest-only replay:** completion caching and state revision writes are not concurrency locks. The adapter does not use revision compare-and-swap; simultaneous requests may race. UI-state writes likewise merge onto the row read at authorization (`web/lib/runtime/openai.ts` `runCompletionPipeline`, `web/app/api/sessions/[id]/ui-state/route.ts`).
- **Recording limits:** missing bucket disables web egress; egress failure does not fail activation. Playback signing is not proof a file exists. `web/lib/livekit.ts` prefers `AWS_S3_BUCKET`, while `web/lib/s3.ts` prefers `S3_BUCKET` if both are configured (`recordingOutput`, S3 module constants).
- **Existing shortcuts:** gateway-only workflow reports; exact normalized-text twin question aggregation; fixed English deadline goodbyes; 60-second greeting-hold cap. Their upgrade conditions live in `web/lib/report-model.ts`, `web/lib/twin/stats.ts` `mostAsked`, `agent/src/agent.py`.

## Open questions

1. **Should end-status webhooks populate dedicated audio playback?** The webhook constructs `s3AudioKey`, but passes it to `closeInterviewSession`, whose forwarding only includes transcript/evidence/replaceTranscript. A no-status webhook calls `finalizeInterviewSession` directly and can save it. Audio playback reads only the dedicated column, not evidence's `audioS3Key` (`web/app/api/sessions/webhook/route.ts`, `web/lib/session-lifecycle.ts`, `web/app/api/sessions/[id]/audio/route.ts`).
2. **How should direct role-play idempotency keys be scoped?** Deployment keys omit userId; lookup/resume is outside the credits lock and does not verify owner/org; concurrent callers can check the key before either creates it. Twin calls now use fresh keys only, so this question concerns the role-play branch (`web/lib/interview-sessions.ts:296–319,352`; unique activationKey in `web/prisma/schema.prisma`).
3. None about reviving failed/revoked rows: the finalizer now retains their status/end and writes no usage. Abandoned → completed remains a rule mismatch for twin first-end semantics (`web/lib/interview-sessions.ts:83–102`).
4. **Which report selection must remain pinned?** Dispatch and webhook transcript policy inspect current agent data, but role-play report input prefers pinned data. Editing `after.report` between start and end can therefore change routing or readiness expectations (`web/lib/session-close.ts`, `web/app/api/sessions/webhook/route.ts`, `web/lib/roleplay/session-report.ts`).
5. **Is a marker without transcript enough for final readiness?** For workflow report kinds, an authenticated webhook sets `transcriptFinal` even if it supplies no nonempty transcript. The workflow treats that marker as ready and may use the browser's transcript (`web/app/api/sessions/webhook/route.ts`, `web/workflows/steps/twin-session-report.ts`, `web/workflows/steps/roleplay-session-report.ts`).
