# Sessions

> A session is one practice conversation, not the user's sign-in session. This module starts the conversation, connects the browser to LiveKit, saves its ending and evidence, records time used, and starts the right report. It also exposes the session-bound runtime and workspace routes. The main owners are `web/lib/interview-sessions.ts`, `web/lib/session-activation.ts`, and `web/lib/session-lifecycle.ts`.

## Who uses it

- **Learner:** starts or resumes their own voice practice, attaches allowed documents, ends the call, and leaves feedback. Routes resolve the signed-in user and organization through `web/lib/session-user.ts` `resolveSessionUser`; ownership checks live in `web/app/api/sessions/*`.
- **Org admin and team:** try agents using org credits for billed voice calls (free when unbilled; studio chat unmetered), list org sessions, and read learners' snapshots and recordings. See [Organizations and roles](orgs-and-roles.md). Pointers: `web/lib/interview-sessions.ts` `activateSession`, `web/app/api/sessions/route.ts` GET, `web/app/api/sessions/[id]/route.ts` GET.
- **Voice agent and session browser:** use separate call tokens. The agent's token authorizes web model completions; the browser's token authorizes commands, UI state and snapshots. Voice Start strips `agentToken` from its response. The agent uses the shared service secret for the completion webhook. Chat Start still returns the agent token as `conversationToken` (Mismatches). Pointers: `web/lib/interview-sessions.ts` `authorizeRuntimeSession`, `authorizeBrowserSession`; `web/app/api/sessions/route.ts:49–55`; `web/lib/session-activation.ts:66`; `web/app/api/sessions/webhook/route.ts` `authorized`.
- **API integrator:** reads role-play session results through the public API; this is not the runtime-token API. See [Public API](public-api.md); `web/app/api/v1/sessions/route.ts`.

[Practice](practice.md) sets twin calls, role-play rules 17–21 and ending/report/token rules 22–28; [People](people.md) supplies membership/refusals. Role-play link access is shared with the page through `roleplayAccessByCode`; live resume and new creation use separate lock branches. Remaining differences are under Mismatches.

## Data

### Session record

`web/prisma/schema.prisma` `InterviewSession` owns these fields. Statuses are strings, not a Prisma enum.

| Fields | Meaning / writer |
| --- | --- |
| `id`, `orgId`, `userId`, `agentId` | Call identity, org and owner; activation writes them. |
| `shareCode`, `activationKey` | Unique call code and nullable unique activation key; activation writes them. |
| `deploymentId`, `assignmentId`, `twinAssignmentId`, `mode` | Launch/access links; `mode` defaults to `voice`, also supports `chat`. |
| `personaSlug`, `personaVersion`, `agentSlug`, `agentVersion`, `compiledSnapshot` | Start-time configuration references and compiled data; activation writes them. |
| `contextId`, `contextName` | Legacy primary document; additional documents use the join table. |
| `status`, `createdAt`, `startedAt`, `endedAt`, `deletedAt`, `attempt` | Lifecycle, soft deletion and attempt metadata; `attempt` defaults to 1. Normal activation creates a new row, not an incremented attempt. |
| `runtimeTokenHash`, `runtimeState`, `runtimeRevision`, `lastCompletion`, `warmOpening` | Runtime authorization, progress, latest completion replay, and best-effort opening preparation. |
| `allowedSeconds`, `chargesOrg` | Nullable start-time learner or billed-studio allowance; usage is capped at it. `chargesOrg` selects staff `org_usage`, not learner `usage`. Live billed studio calls hold the whole allowance (`web/lib/org-credits.ts` `runningSeconds`). |
| `livekitRoom`, `livekitDispatchId`, `videoEgressId`, `audioEgressId` | Transport/recording references. Current web activation writes room, dispatch and video egress, not audio egress. |
| `transcript`, `evidence`, `s3AudioKey` | Conversation lines, accumulated evidence, and dedicated audio location. |
| `endWorkAt` | Time `startSessionEnd` successfully started the end workflow and saved the marker; null means the sweep/disable can retry recent ended calls. Migration `20261116120000_session_end_work` sets it to endedAt for already-ended rows. |
| `report`, `reportStatus`, `reportWorkflowRunId` | Stored report JSON, processing status, and claiming end-workflow run ID. Twin/builder role-play saves and failures require that ID and generating status (`web/lib/report-model.ts:72–82`). |
| `feedbackRating`, `feedbackNote` | Owner's latest rating and note. |

Writers: `web/lib/interview-sessions.ts`, `web/lib/session-activation.ts`, `web/lib/runtime/openai.ts`, `web/lib/session-warm.ts`, `web/app/api/sessions/webhook/route.ts`, `web/lib/session-end.ts`, and the report/feedback owners below.

`InterviewSessionDocument` has composite key `(sessionId, documentId)` and a creation time. Activation and the documents route add links; deleting either parent cascades links. `WorkspaceCommand` has globally unique `id` (the tool call ID), `sessionId`, `tool`, `input`, `status`, `result`, and completion timestamps. Its lifecycle is `pending → completed | failed`. Pointers: `web/prisma/schema.prisma`, `web/lib/workspace-commands.ts`.

A session cannot have both assignment kinds (`session_one_assignment_kind`); twin sessions must be voice. DB access checks are also enforced by triggers in `web/prisma/migrations/20261027020000_twin_access/migration.sql`.

### Lifecycles

| State / transition | What actually writes or accepts it |
| --- | --- |
| `assigned` | Schema default and legacy `createAssignedSession`; ordinary activation creates a separate `activating` row. The legacy helper is retained for local scripts, not assignment starts (`web/lib/interview-sessions.ts`). |
| new → `activating` → `active` | Create snapshot/state, initialize chat, then stamp `startedAt` and token hash (`activateSession`). |
| `activating` / `active` → `failed` | Chat initialization or later LiveKit activation failure (`activateSession`, `web/lib/session-activation.ts`). |
| → `completed` / `abandoned` | Shared finalizer on explicit ending, replacement, disable or stale sweep; status and usage commit together. `completed` cannot be downgraded; `abandoned` can later become `completed` (`finalizeSessionRow`, `resolveSessionEndStatus`, `sweepStaleCalls`). |
| `closing` | Accepted by runtime authorization, but these lifecycle functions do not set it (`authorizeRuntimeSession`). |
| `assigned` → `revoked` | Member disabling; open `activating`/`active` calls instead close as `abandoned` (`web/lib/members.ts` `setMemberDisabled`). |
| failed row → deleted → new activation | A retry with the same activation key deletes the failed row first (`activateSession`). |

Report lifecycle is independent: null/`none → generating → completed | failed`; failed is never re-claimed. A report failure does not make the call status failed. Twin and builder role-play writers use the claiming run ID; legacy v1 still writes directly (Mismatches). Pointers: `web/lib/session-close.ts:41–47`, `web/workflows/steps/session-end.ts`, `web/lib/report-model.ts:72–111`, `web/lib/generate-session-report.ts`.

## How it works

### 1. Activate or resume

1. `POST /api/sessions` resolves user/org; either missing is `signed_out`/401/“Sign in first.” A share code or agent slug is required (`invalid_input`/400/“shareCode or agentSlug is required”). `deploymentKey` is removed from the route and activation types; a key alone cannot start. Without a code, the route checks enabled membership and admin/team (`studio_only` for learners). Literal `mode: "chat"` selects chat, everything else voice; literal `calibrate: true` requests calibration. Only one `contextId` is forwarded. (`web/app/api/sessions/route.ts:21–48`; `web/lib/session-activation.ts:15–29`.)
2. `activateSession` checks `practicePerson` first (`no_org` / `member_disabled`); learner calibration is `studio_only`. Role-play codes use the page's `roleplayAccessByCode`: same-org lookup → enabled member → account ownership (`roleplay_not_assigned`) → pending/legacy used (`roleplay_access_removed` otherwise) → unarchived agent/active deployment (`not_found`) → allowed voice (`mode_not_allowed`). Dates are ignored. If no role-play link matches, `twinAccessByCode(join: false)` checks twin access without joining; unknown/other-org code is `not_found`/404. The service also refuses learners without a code, even if assigned by name. (`web/lib/interview-sessions.ts:220–281`; `web/lib/roleplay-access.ts:22–40`; [Twins](twins.md), [Role plays](roleplays.md).)
3. Every twin start gets fresh `twin:<random>` and never resumes. Assigned role plays select the latest live assignment/user key outside the lock, or make `assignment:<id>:<random>`; caller idempotency key is ignored. Direct studio role plays use `deployment:<deploymentId>:<idempotencyKey>`, otherwise `direct:<random>`. Direct studio role plays do not check deployment status/allowedModes. Twins refuse chat with `voice_only`; personal role-play links refuse it with `mode_not_allowed`/400/“This role play can't be started as chat.” (`web/lib/interview-sessions.ts:244–281`; `web/lib/roleplay-access.ts:37–38`; `web/lib/deployments.ts` `ensureDeployment`.)
4. For a matching activating/active row, `minutes:<org>` protects a conditional token-hash update **only while live**. A winner returns the same ID/stored mode/status, `resumed: true` and `max(0, allowedSeconds - floor(elapsed))` from startedAt or createdAt. Resume replaces no calls, repeats no chat initialization, and bypasses allowance/snapshot checks. If that row ended before the update, Start makes a new random key. A failed matching row is deleted; another ended one-off key is `not_found`. The lookup and access checks are still outside this resume lock (Mismatches). (`web/lib/interview-sessions.ts:282–303`.)
5. New calls load the unarchived same-org agent and ready documents, validate document owner/type/size and `preUpload`, and compile/pin data and versions before the lock. Context errors are uncoded 400; disallowed Before uploads use `invalid_input`. Session snapshot versions come from these reads, not the lock. (`web/lib/interview-sessions.ts:125–144,305–320`; `web/lib/session-activation.ts` `startRefusal`; [Platform](platform.md).)
6. Studio voice refreshes org credits before `minutes:<org>`. In its 15-second creation transaction, Start rechecks person, pending/used role-play link status and agent archive (or twin assignment status/accessUntil), and agent existence/archive. It then ends/charges this person's other live org calls, checks `startAllowance`, creates the activating row/documents and optional twin calibration. Refusal rolls back all those ends/writes. This is a partial access recheck: deployment status/modes, rotated code/owner, documents and prior studio/calibration role are not repeated. (`web/lib/interview-sessions.ts:322–386`; `web/lib/db.ts` `withLock`.)
7. `startAllowance` checks local pause then the five-minute learner/billed-studio floor: under 60 seconds `credits_out` / `org_credits_out`; 60–299 `credits_short` / `org_credits_short`; ≥300 becomes the learner allowance; billed studio allowance is capped at `MAX_STUDIO_CALL_MINUTES * 60` (currently 1,800 seconds). The same stored value limits the reservation, deadline and final charge for twins, calibration and role plays, with no automatic extension. Unbilled studio has null allowance. Studio chat and live resume bypass this helper. The link page calls it even when an existing call could resume. (`web/lib/practice.ts:22–63`; `web/lib/pages/learner.ts:108–111`; `web/lib/interview-sessions.ts:282–298,345`; [Credits](credits.md), [Billing](billing.md).)
8. After commit, schedule replaced usage/end work, then initialize chat with session ID/org/mode. Only a still-activating row becomes active with startedAt/token hash. If already ended, `call_replaced`/409; chat failure only fails a still-activating row. Missing secret before the try can leave it activating. No start, end or failure writes role-play `used` status or `usedAt`. (`web/lib/interview-sessions.ts:388–416` `activateSession`; `finalizeSessionRow`; `web/lib/session-activation.ts:131–143`.)
9. `runSessionStart` awaits open then voice connect in the start workflow (zero retries), with inline fallback only on workflow startup failure. `startRefusal` keeps AppError code/status/message; selected context errors remain uncoded. Null fallback is now `not_found`/404/“Not found.” Success includes the browser token as session.runtimeToken, plus participant/room or chat conversationToken, and new-call calibrationId. POST removes the internal agentToken; chat conversationToken is still that agent token. Remote setup failures do not roll back committed calls/calibrations. Best-effort opening warmup is Next `after()`; unexpected errors return generic 500. (`web/lib/run-session-start.ts`; `web/lib/session-activation.ts:39–67`; `web/workflows/start-session.ts`; `web/app/api/sessions/route.ts:50–57`.)

### 2. Connect LiveKit and release the greeting

1. Resolve a ready voice: explicit agent voice first, otherwise persona voice; accept only same-org/global voices. If unavailable, try the alphabetically first ready global voice (`web/lib/session-activation.ts` `connectVoice`). See [Personas and voice](personas-and-voice.md).
2. Room name is the session ID. Create it with empty timeout 600 seconds and departure timeout 30 seconds, or update existing room metadata. Reuse a dispatch for the configured agent name, otherwise create one. Room metadata contains `sessionId`, `orgId`, `agentSlug`, `hold_opening`, optional voice, absolute `ends_at`, and agent kind, with no token. Dispatch metadata has those fields plus the agent's runtime token; reusing a dispatch does not rewrite its metadata (`web/lib/livekit.ts:86–106` `activateLiveKitSession`).
3. When a bucket exists, reuse an egress in status 0/1/2 or try a room-composite MP4 recording, H264 1080p30, mixed audio plus screen/speaker tiles. Key: `<S3_BASE_PREFIX>/<orgId>/recordings/<sessionId>/video.mp4`; prefix defaults to `trainertwin-dev`. Egress failure only warns. The expected key can be saved even when egress did not start (`web/lib/livekit.ts`).
4. Store room, dispatch, egress ID and video key; return participant JWT/room. Identity is `user-<userId>`. A resumed join failure rethrows without closing or failing the joined call. A new-call failure cleans up previously read room refs and marks failed only if activating/active. Neither changes the assignment. (`web/lib/session-activation.ts:115–143`; `web/lib/livekit.ts`.)
5. Hold the greeting if the agent has an intro video or the caller requests it. `SessionView` starts with `holdOpening: true`; after launch, connection, agent arrival and any intro, it applies mic/camera choices and sends reliable `{ type: "begin-opening" }`. The Python agent buffers typed input and gates audio while held, with a 60-second release timeout. This is not an unbounded pause (`web/components/session-view.tsx`, `agent/src/agent.py` `TrainerAgent`, `OPENING_RELEASE_TIMEOUT`). Runtime behavior belongs to [Voice agent and chat](voice-agent-and-chat.md).

### 3. End the call and save transcript/evidence

- A refused/failed browser start keeps `startedRef` set throughout the five-second get-ready countdown: no repeated POST each tick. Only explicit “Try again” resets it. `DUPLICATE_IDENTITY` room disconnect (the same user joined in another tab) returns without finalizing; other disconnects still end normally. (`web/components/session-view.tsx:924–929`, start/countdown effects.)
- The browser derives a deadline from `launch.session.secondsLeft`. A non-manual end at or after 30 seconds before that deadline is `time_up`, finalized as completed. The end card says “Time's up”: learners are directed to their trainer for more minutes; studio users are told the call reached its time limit and they may start another if the org has enough credits, not that its entire balance is empty. Learner feedback includes the time-up explanation above the form. Manual endings remain manual even near the deadline (`SessionView` `handleDisconnect`, `TIME_UP_MARGIN_MS`).

- `closeInterviewSession` calls `finalizeInterviewSession`, which runs `finalizeSessionRow(input, tx)`: it locks the row with `SELECT ... FOR UPDATE` before reading/merging; status, transcript/evidence, first observed end time, token clearing and `writeSessionUsage` commit together; role-play assignment state is not changed. A usage-write failure rolls back the end instead of leaving a saved uncharged row. Meteroid reporting is scheduled after commit. Only the transaction that changed status (`endedNow: true`) calls `startSessionEnd` (TWIN → end-twin-session, otherwise end-roleplay-session). The workflow strictly closes LiveKit and safely retries charge, then scores a twin calibration or claims/generates a report. Lookup, enqueue or marker-save failure is caught: strict close/charge is attempted inline, failures are logged, and no report/calibration score is generated inline. `startSessionEnd` never throws; a null endWorkAt remains eligible for retry by sweep/disable. A marker-save failure after successful enqueue can cause another workflow start (`web/lib/session-end.ts:21–32`). (`web/lib/interview-sessions.ts:54–131`; `web/lib/session-lifecycle.ts`; `web/lib/session-end.ts`; `web/lib/session-close.ts`.)
- Browser finalization requires the owning user, an enabled member in the same org, an undeleted call and requested status completed or abandoned. Declared Content-Length and actual UTF-8 `Buffer.byteLength(text)` must each be ≤1,048,576 bytes; larger is invalid_input/400 with “This call's end is too big to save (over 1 MB).” Missing sessionId/invalid status is invalid_input/400; missing, other-owner/org or deleted call is not_found/404; disabled membership is member_disabled/403. It keeps transcript object entries with string text, ignores evidence, s3AudioKey and transcriptFinal, and does not use a strict body schema. `SessionView` sends only sessionId/status/transcript, uses keepalive only when serialized body.length <60,000 characters, checks HTTP success and keeps a visible retry error on failure. This guard counts characters, not bytes (Mismatches). (`web/app/api/sessions/finalize/route.ts:19–59`; `web/components/session-view.tsx:486–525`.)
- Serialized finalization keeps the first `endedAt`, including overlapping abandoned/completed ends, clears the token hash, and never downgrades completed. Requested abandoned changes only activating/active/closing; requested completed also permits abandoned → completed. Completed/failed/revoked/assigned retain their status/end; same-status retry enriches data but does not clear the token/write usage/start end work again (endedNow=false). A linked role-play assignment keeps its status and usedAt on completed/abandoned. Evidence is a shallow merge; incoming keys replace matching old keys (`web/lib/interview-sessions.ts` `finalizeSessionRow`, `mergeSessionEvidence`).
- Normally the first nonempty transcript wins. For report kinds other than legacy `session`, the authenticated agent webhook may replace it with a nonempty full transcript and marks `evidence.transcriptFinal = true`; this includes twin calibrations. Empty incoming transcripts never clear an existing one (`web/lib/session-after.ts` `usesAgentTranscript`, `web/app/api/sessions/webhook/route.ts`, `web/lib/interview-sessions.ts`).
- Agent transcript lines are `{ role: "user" | "trainer", text, spokenAt? }`, where `spokenAt` is epoch milliseconds. They come from voice-session history at shutdown. Report readers classify `role: "user"` or `speaker: "learner"` as learner; other roles are treated as the AI. `transcriptTurns` joins adjacent learner pieces except standalone “Feel(s) off” messages, using the shared `isFeelsOffMessage` predicate (see [Voice agent and chat](voice-agent-and-chat.md)). (`agent/src/agent.py` `on_session_end`, `web/lib/twin/stats.ts:27–29,136`, `web/lib/generate-session-report.ts`).
- After saving, browser finalize registers `after()`: create the learner memory collection, then start addMemory for the effective saved learner lines under key session_<id>. Neither collection creation nor memory saving delays the reply; failures log. It still awaits `closeInterviewSession`, including usage scheduling and end-work startup/fallback, before returning (Mismatches). Browser finalize and recognized-status agent webhook share closeInterviewSession; PATCH /api/sessions and POST /api/sessions/recording are deleted. (`web/app/api/sessions/finalize/route.ts:56–96`; `web/lib/session-lifecycle.ts:17–25`; `web/lib/interview-sessions.ts:54–57`; `web/app/api/sessions/route.ts`.) See [Knowledge](knowledge.md) for memory storage.

### 4. Agent completion webhook

`POST /api/sessions/webhook` is service-secret authenticated, not cookie or runtime-token authenticated. It compares bearer bytes with `COPILOT_SERVICE_SECRET` using equal length and constant-time comparison **before parsing JSON or querying the DB**. Missing secret or credentials returns 401 (`web/app/api/sessions/webhook/route.ts` `authorized`).

| Payload | Accepted behavior (`payloadSchema`, POST in that route) |
| --- | --- |
| `session_id`, `sessionId`, `room_name` | Nullable strings, max 200 each; first truthy value wins, then trim and remove leading `session-`. Find by ID or session share code. Missing identifier: 400; no matching row: 404. |
| `status` | Nullable string, max 40. `COMPLETED → completed`; `FAILED`/`ABANDONED → abandoned`. Other strings or omission perform an evidence/transcript-only update, not a status transition. |
| `transcript` | Nullable array, max 10,000 lines. Each has string `role` ≤40, string `text` ≤50,000, optional nullable nonnegative numeric `spokenAt`; extra line fields are allowed. |
| `report`, `metrics` | Nullable record / optional arbitrary value. `report` fields merge into evidence, not the generated `report` column. Truthy metrics are stored in evidence. |
| `video_url`, `video_s3_key`, `audio_url`, `audio_s3_key`, `participant_identity` | Nullable strings ≤2,000. Explicit video_s3_key is kept only when orgOwnKey(session.orgId, key) passes; URL/audio fields become evidence unchanged. participant_identity is accepted but not persisted. report fields are merged first and can also carry media keys; signing checks video keys again. |

Malformed JSON/schema returns 400 (up to five validation issues). The handler tries to obtain recording start time from LiveKit egress, ignoring lookup failure. It saves that as epoch milliseconds for report timing. A recognized end status closes the room and finalizes; an unrecognized status calls the finalizer without ending. Same-status/concurrent losing endings enrich saved data but do not start another workflow; abandoned → completed does when it wins its status update (endedNow). No-status webhook never starts an end workflow. Startup failure logs and falls back to close/charge without an inline report; recent unstarted end work is retried by sweep/disable; successful webhook response is `{ ok: true, sessionId, status }` (`web/app/api/sessions/webhook/route.ts`, `web/lib/livekit.ts` `recordingStartedAt`).

The producer sends bearer service auth, refuses to send without a configured secret, uses a 15-second request timeout, and retries once after two seconds **only for HTTP 5xx**, not general connection errors or 4xx. Errors are logged rather than propagated (`agent/src/recording/webhook.py` `post_completion_webhook`).

### 5. Usage and recordings

- An end-status finalization that wins the status transition (endedNow) calls `writeSessionUsage(tx, sessionId)` **inside** the end transaction. Usage is whole elapsed seconds, floored, clamped to zero/allowance. Missing row/allowance/end or a currently failed/revoked row writes none; missing start writes a zero-second row for an ended metered call. `createMany(skipDuplicates)` and unique sessionId make retries no-ops. `chargesOrg` chooses `org_usage`, otherwise `usage`; only a newly written positive staff charge asks the caller to report Meteroid usage after commit. `recordSessionUsage` is the standalone idempotent workflow retry. Transcript-only finalizer updates do not charge. Learner live calls count capped elapsed time; studio live calls hold their whole allowance. (`web/lib/interview-sessions.ts:54–56,121–130`; `web/lib/minutes.ts:224–251`; [Credits](credits.md).)
- Provider/model usage is separate from learner seconds. Web runtime meters one turn's accumulated usage by request hash; reports meter model generations; the voice agent flushes usage on shutdown. See [Platform](platform.md) and [Voice agent and chat](voice-agent-and-chat.md). Pointers: `web/lib/runtime/openai.ts`, `web/lib/report-model.ts`, `web/lib/generate-session-report.ts`, `agent/src/agent.py` `on_session_end`.
- Current web activation records composite video with audio. The Python `recording/egress.py` contains separate audio/video helpers, but current `agent/src/agent.py` does not call them. Do not assume every session gets a separate audio file (`web/lib/livekit.ts`, `agent/src/recording/egress.py`).
- No browser/agent raw-recording upload route remains. Recordings come from LiveKit/server references and the service-secret webhook (`web/lib/livekit.ts`; `web/app/api/sessions/webhook/route.ts`; deleted web/app/api/sessions/recording/route.ts).
- Playback uses visibleSessions: owner or enabled admin/team in the same org, deletedAt=null, redirect to a one-hour S3 signed GET. Video accepts evidence.videoS3Key only through orgOwnKey, otherwise uses the expected composite key. orgOwnKey requires the exact orgPrefix plus slash and rejects any key containing `..`. Public role-play GET uses the same guard but falls back only with videoEgressId. No existence check occurs. Audio signs the dedicated s3AudioKey without that org guard (Mismatches). (`web/lib/session-user.ts:46–49`; `web/lib/s3.ts:135–137`; `web/app/api/sessions/[id]/video/route.ts:27–31`; audio route:15–20; `web/app/api/v1/sessions/[id]/route.ts:37–53`.)

### 6. Generate and show reports

After the end is saved, `startSessionEnd` chooses the workflow by current Agent.kind. Both run closeRoom (strict retries, exhausted errors ignored) → chargeCall. The twin workflow then checks calibration before takeReport; the roleplay workflow proceeds to takeReport. closeLiveKitSession strict ignores 404/not_found/failed_precondition but propagates other failures; ordinary non-strict callers retain best-effort behavior (`web/lib/session-end.ts`; `web/lib/livekit.ts`; `web/workflows/end-twin-session.ts:19–29`; `web/workflows/end-roleplay-session.ts`; `web/workflows/steps/session-end.ts`).

For a twin calibration, `readCalibration` returns none without a calibration row, ready only for `evidence.transcriptFinal === true`, otherwise waiting. The end workflow waits at most twelve 10-second sleeps, then calls the scoring step and returns `{status: "ended", calibration: "scored"}` without a learner-report claim. Timeout uses the saved provisional transcript, including an empty one. `scoreCalibration` has three retries and calls `scoreCalibrationOnce`: an atomic `scoreClaimedAt` claim on an unscored row (null or older than two minutes), followed by transcript/ratings read, Jev classification and counts/`scoredAt` save. No questions saves raw counts without Jev. Model/save failure clears the claim and throws. Missing, already-scored or recently claimed rows return null; the step ignores that result, so “scored” is a workflow branch label, not proof of a saved score. Full count/rating rules belong to [Twins](twins.md#calibrate-and-save-results). (`web/workflows/end-twin-session.ts:22–26`; `web/workflows/steps/calibration.ts:9–22`; `web/lib/twin/calibration-score.ts:71–103`.)

reportFor reads current after.report through reportKindOf: explicit twin/roleplay, otherwise twin for TWIN or session for v1. Calibrations are excluded on the twin path. Completed twin calls qualify; abandoned twin calls qualify only when saved transcript already has learner speech. Roleplay/session require completed. claimReport atomically updates an ended row with null/none report status to generating and sets reportWorkflowRunId to the current **end** run. A lost claim runs no report (`web/lib/session-close.ts` `reportFor`, `claimReport`; `web/lib/session-after.ts`; `web/workflows/steps/session-end.ts` `takeReport`).

### 7. Documents, commands, UI state and web completions

- **Attach a document:** owner-cookie auth; call must be undeleted and activating/active. Use pinned before settings, falling back to current agent data; require `duringUpload`. Accept only ready same-org documents owned by this user, PDF ≤10 MB or image ≤5 MB. Add the join link idempotently and, if a snapshot exists, append document ID/manifest once. The next runtime turn can read the updated snapshot (`web/app/api/sessions/[id]/documents/route.ts`). File creation/expiry is [Platform](platform.md), not this route.
- **Run a command:** studio enqueues by tool call ID only for activating/active sessions in its org; upsert never changes an existing command. Browser polls pending commands oldest first and acknowledges result or failure using its browser token (authorizeBrowserSession). Only pending commands can be completed, so duplicate acknowledgments do not rewrite results. Enqueue waits up to 60 × 500 ms; other commands time out as pending, but `finish_session` closes as completed even on timeout. This close uses closeInterviewSession and therefore starts the end workflow on status change (`web/lib/workspace-commands.ts`, `web/app/api/sessions/[id]/commands/route.ts`, `web/app/api/sessions/[id]/commands/[callId]/route.ts`). Tool availability belongs to [Voice agent and chat](voice-agent-and-chat.md).
- **Report UI state:** browser-token POST stores `{ active, key, updatedAt }` under `runtimeState.uiState`. Allowed surfaces are code, canvas, pdf, image, presentation; anything else becomes null. Key is truncated to 120 characters. Invalid/non-object body is 400. GET returns that state or null; it does not execute an action (`web/app/api/sessions/[id]/ui-state/route.ts`).
- **Web completions:** `POST /api/v1/chat/completions` delegates to `handleCompletions`. It uses a runtime bearer token, not an external API key; missing/invalid token gives OpenAI-shaped 401. Bad JSON gives 400. This is the web deterministic runtime adapter, separate from the chat-service initialization above (`web/app/api/v1/chat/completions/route.ts`, `web/lib/runtime/openai.ts`).
- The web adapter defaults `messages=[]`, `stream=true`, `tools=[]`; compiles the pinned snapshot (loads one if absent), updates runtime/evidence/transcript, and increments revision. It caches **only the latest** completion by normalized messages plus token hash/session ID. Repeating that hash returns cached JSON or SSE with `X-Idempotent-Replay: true`, without another grading pass. New responses expose `X-Execution-Count`; SSE ends with `[DONE]` and includes usage. This is buffered SSE, not token-by-token provider streaming (`web/lib/runtime/openai.ts` `runCompletionPipeline`, `computeRequestHash`, `buildSseStream`).
- Missing specs return 500. Pipeline exceptions become generic OpenAI-shaped 500, not raw exception details; individual direction/analysis/retrieval stages also have fallback paths. This error wrapper begins after authorization and JSON parsing (`web/lib/runtime/openai.ts` `handleCompletions`, `runDirectionCheck`, `runAnalyzerLLM`).

## Rules

1. Activation never creates an org member or twin assignment; twin codes use join=false and a nonmember direct common-code start is refused. Page opening owns common-link joining (`web/lib/pages/learner.ts` `loadSharedSession`; `web/lib/twin-access.ts` `twinAccessByCode`). Every activateSession path rejects absent/disabled membership in its initial check; new creation repeats that check under the lock. Post-check/setup races remain below. Billed admin/team voice calls require at least 5 org credits and set chargesOrg/allowedSeconds; staff chat and unbilled staff voice remain unmetered. Learners require at least 5 personal minutes for a new voice call (`web/lib/interview-sessions.ts` `activateSession`).
2. Twins cannot start chat (`voice_only`). Role-play links only allow voice and must list it in deployment allowedModes (`mode_not_allowed`); direct studio role plays bypass that deployment check. Both route and service refuse learners by name (`studio_only`); no deploymentKey input remains. Twin starts use fresh keys and never resume. (`web/lib/interview-sessions.ts:235–281`; `web/lib/roleplay-access.ts:37–38`; `web/app/api/sessions/route.ts:25–48`.)
3. Pending and legacy used role-play links remain usable without timestamp expiry; completed calls permit new practice. Start/finalize/join failures never write used/usedAt. Resume's conditional live-status update is inside the minutes lock; if it loses to an end, a new call is attempted instead. (`web/lib/interview-sessions.ts:282–303,399–416` `activateSession`, `finalizeSessionRow`; `web/lib/session-activation.ts:131–143`.)
4. Resuming cannot reset `startedAt` or replenish `allowedSeconds`; it returns remaining time, even zero, and is not refused because the org is paused. New voice calls are refused while paused with 403 and the learner/studio message above, using only the app's pause flag (`web/lib/interview-sessions.ts` `activateSession`; `web/lib/billing/paused.ts` `pausedReason`; [Billing code](billing-code.md)).
5. A new call by any role ends the user's other activating/active calls, writes their usage and checks allowance under `minutes:<org>` in one transaction; refusal rolls it all back. Runtime setup is after commit, so this is serialized creation, not a database one-live-call constraint or protection against later resurrection (`web/lib/interview-sessions.ts:352–428`; `web/prisma/schema.prisma`).
6. Agent authorization accepts only hashes on activating/active/closing rows. Browser authorization recomputes its HMAC and accepts activating/active only. Finalization clears the agent hash and changes status, voiding both tokens for their respective routes. Commands/UI state return runtime_token_invalid/401 for missing, wrong, agent or ended tokens. Snapshot returns the same for a nonempty invalid bearer, without trying cookies; no bearer uses owner/studio cookie visibility. No PATCH or recording upload remains (`web/lib/interview-sessions.ts:422–469`; `web/app/api/sessions/[id]/{commands,ui-state}/route.ts`; snapshot route:20–61).
7. Webhook auth runs before parsing and mutation; browser cookies and runtime tokens do not substitute for its service secret (`web/app/api/sessions/webhook/route.ts`).
8. Only live rows (plus abandoned → completed) can transition; completed, failed, revoked and assigned keep their status/end. endedNow gates token clearing, usage and dispatch; duplicate same-target ends start end work once. Transcript/evidence may still be enriched. Sequential retries retain the first end time; evidence merges shallowly (`web/lib/interview-sessions.ts` `finalizeSessionRow`).
9. Nonempty final agent transcripts replace browser transcripts only when `usesAgentTranscript` is true. Legacy session-report calls retain their first nonempty transcript (`web/lib/session-after.ts`, `web/app/api/sessions/webhook/route.ts`).
10. Usage is capped at the original allowance and inserted once per session **in the transaction that ends it**. Currently failed/revoked rows get no ledger row; an ended metered call with no start gets a zero row. Post-commit Meteroid reporting and workflow `recordSessionUsage` retries cannot debit twice (`web/lib/interview-sessions.ts` `finalizeSessionRow`; `web/lib/minutes.ts` `writeSessionUsage`, `recordSessionUsage`; see [Credits](credits.md)).
11. End workflows atomically claim completed/abandoned rows with null/none report status; generating/completed/failed claims lose. Report eligibility narrows abandoned to twin learner speech; reportWorkflowRunId is the claiming end run. Twin calibrations bypass that claim and use their own scoring claim/three-retry step after final-transcript readiness or its wait, for both completed and abandoned ends. (`web/lib/session-close.ts`; `web/workflows/steps/session-end.ts`; `web/workflows/end-twin-session.ts:22–29`; `web/workflows/steps/calibration.ts`.)
12. Feedback is owner-only on completed/abandoned calls. Strict body: integer rating 1–5, required trimmed note ≤500 characters, no extra fields. Empty note stores null; repeat submission overwrites the two fields (`web/app/api/sessions/[id]/feedback/route.ts`).
13. Document attachment must pass both ownership and pinned permission checks; a hidden UI control alone is not authorization (`web/app/api/sessions/[id]/documents/route.ts`).
14. A command acknowledgment cannot change a completed/failed command; unknown/already-acknowledged IDs still get `{ ok: true }` from the route (`web/lib/workspace-commands.ts` `completeWorkspaceCommand`, acknowledgment route).
15. Sweep runs every five minutes: select at most 200 stale live rows, separately restart at most 200 completed/abandoned calls with endWorkAt=null and endedAt from one minute to 24 hours ago, fail old generating reports, then end the selected live calls. Live thresholds remain ten minutes activating, allowance + two minutes active, or three hours without allowance. It continues after per-live-call failure; query/report-repair failures escape. Disable also restarts that owner's unstarted completed/abandoned work within the past day, including repeat disable. Historical ended rows are backfilled, not retried (`web/lib/session-lifecycle.ts:40–67`; `web/lib/members.ts:60–76`; `web/prisma/migrations/20261116120000_session_end_work/migration.sql`; `web/vercel.json:19–20`).

## Edge cases and limits

- End/usage commit together; enqueue and endWorkAt save are separate. Same-status retry does not start an end run, but sweep/disable recover recent null-marker calls. Concurrent repair or enqueue-success/marker-failure can start duplicate end workflows; report claims prevent duplicate twin/builder saves. Once endWorkAt is set, failed/interrupted close/charge/report/scoring work is not restarted by this scan. An abandoned call without learner speech at takeReport is ineligible; later same-status/no-status transcript enrichment does not start a new run. Late transcript after completed report does not regenerate it (`web/lib/session-end.ts:21–32`; `web/lib/session-lifecycle.ts:24,49–59`; `web/lib/session-close.ts:27–47`).

- **Activation failure:** chat failure only fails a still-activating row. Resumed LiveKit join failure leaves the original call untouched and rethrows; new-call LiveKit failure cleans up previously read refs and fails only activating/active. No assignment usage reset remains. The HTTP route returns selected coded refusals or generic 500. New resources created before a failing DB save may not yet be stored for cleanup. (`web/lib/interview-sessions.ts:397–412`; `web/lib/session-activation.ts:131–143`; `web/app/api/sessions/route.ts:50–57`.)
- **Initial document list:** `SessionView` sends both `contextId` and `contextIds`, but POST forwards only `contextId` and `startSessionNow` has no `contextIds` parameter. The helper `activateSession` supports multiple documents, but this browser activation path only passes the first (`web/components/session-view.tsx`, `web/app/api/sessions/route.ts`, `web/lib/session-activation.ts`, `web/lib/interview-sessions.ts`).
- **Missing service secret:** a new row is created before `runtimeToken()` is called, and that call is outside the chat-initialization catch. A missing secret can therefore leave an activating row instead of marking it failed (`web/lib/interview-sessions.ts` `activateSession`, `runtimeToken`).
- **Other active studio calls:** now end through `finalizeSessionRow` with usage, followed by `startSessionEnd` after commit, across all twins/agents in that org. Chat/LiveKit failure of the replacement does not restore the old call (`web/lib/interview-sessions.ts:355–424`).
- **Stale calls:** the agent still grants about 30 seconds for empty-room reconnect and ends at the allowance. The web sweeper now selects up to 200 rows per run, without ordering: activating with createdAt strictly older than 10 minutes, or active with non-null startedAt strictly past startedAt + allowance + 2 minutes (3 hours if no allowance). It calls the normal abandoned end path sequentially, clearing token and charging up to allowance; per-call failures log and do not stop the rest. It covers role plays/studio too, ignores active rows without startedAt, and selects age before finalization; the finalizer atomically rechecks live status, not the stale age condition. Its ended counter increments only when endedNow is true; a row already ended by another caller is not counted again. Query failures escape the route; per-call failures still produce `ok: true`. (`web/lib/session-lifecycle.ts:40–67`; `web/app/api/internal/sessions/sweep/route.ts:9–14`; `web/vercel.json`; `agent/src/agent.py` `watch_empty_room`, `end_at_deadline`, `on_session_end`.)
- **Calibration retry limits:** there is no calibration score-run ID, scoring status/poll repair or hour-age scan. Null endWorkAt enqueue recovery exists, but does not repair a started run that later exhausts/fails. A model failure is retried by the scoring step, but exhaustion leaves it unscored; startSessionEnd's enqueue fallback only closes/charges. A model-success/save-failure retry repeats model work. A claim left by a crashed worker can be taken over after two minutes only if another scoring attempt actually runs. Recently claimed rows return null successfully, even when still unscored. Later agent transcripts do not regenerate saved counts. (`web/lib/twin/calibration-score.ts:80–103`; `web/workflows/steps/calibration.ts:18–22`; `web/workflows/end-twin-session.ts:25–26`; `web/lib/session-end.ts:21–32`; `web/prisma/schema.prisma` TwinCalibration.)
- **Report recovery limit:** missing run ID no longer leaves an ended twin/builder report pending forever: reportStateOf times it out and failStaleReports marks it failed. Neither re-claims it. Null endedAt never ages out. Legacy v1 and the one-off twin script bypass parts of this contract (Mismatches). A truncated builder prompt can lose its brief/goals/rubric at the front while keeping the transcript tail (`web/lib/report-model.ts:49,92–116`; `web/lib/roleplay/session-report.ts:189–207`; `web/lib/generate-session-report.ts`; `web/scripts/process-twin-sessions.ts`).
- **Latest-only replay:** completion caching and state revision writes are not concurrency locks. The adapter does not use revision compare-and-swap; simultaneous requests may race. UI-state writes likewise merge onto the row read at authorization (`web/lib/runtime/openai.ts` `runCompletionPipeline`, `web/app/api/sessions/[id]/ui-state/route.ts`).
- **Recording limits:** missing bucket disables web egress; egress failure does not fail activation. Playback signing is not proof a file exists. `web/lib/livekit.ts` prefers `AWS_S3_BUCKET`, while `web/lib/s3.ts` prefers `S3_BUCKET` if both are configured (`recordingOutput`, S3 module constants).
- **Existing shortcuts:** gateway-only workflow reports; exact normalized-text twin question aggregation; fixed English deadline goodbyes; 60-second greeting-hold cap. Their upgrade conditions live in `web/lib/report-model.ts`, `web/lib/twin/stats.ts` `mostAsked`, `agent/src/agent.py`.

## Open questions

1. **Should end-status webhooks populate dedicated audio playback?** The webhook constructs `s3AudioKey`, but passes it to `closeInterviewSession`, whose forwarding only includes transcript/evidence/replaceTranscript. A no-status webhook calls `finalizeInterviewSession` directly and can save it. Audio playback reads only the dedicated column, not evidence's `audioS3Key` (`web/app/api/sessions/webhook/route.ts`, `web/lib/session-lifecycle.ts`, `web/app/api/sessions/[id]/audio/route.ts`).
2. **How should direct role-play idempotency keys be scoped?** `deployment:<deploymentId>:<idempotencyKey>` omits userId; lookup does not verify owner/org, though the conditional live update is now locked. Two studio users supplying the same key can join one user's call; concurrent initial lookups can still collide. Twin calls only use fresh keys. (`web/lib/interview-sessions.ts:267–269,282–303,346–357`; unique activationKey in `web/prisma/schema.prisma`.)
3. **What “End” means is undecided.** Practice leaves this open, not a settled first-end-status bug: /s manual End sends abandoned; /t learner confirmation sends completed. A later agent COMPLETED can promote abandoned calls from disconnect, sweep, disable or replacement and start another end run. The row lock keeps the first end time and merged data. Proposed completed-for-End/live-only-webhook semantics have not been approved (`specs/practice.md` Open questions; `web/components/session-view.tsx:515–519`; `web/components/calibration/calibration-call.tsx` end; `web/lib/interview-sessions.ts:78–104`; `web/app/api/sessions/webhook/route.ts:75–107`).
4. **Which report selection must remain pinned?** Dispatch and webhook transcript policy inspect current agent data, but role-play report input prefers pinned data. Editing `after.report` between start and end can therefore change routing or readiness expectations (`web/lib/session-close.ts`, `web/app/api/sessions/webhook/route.ts`, `web/lib/roleplay/session-report.ts`).
5. **Is a marker without transcript enough for final readiness?** For workflow report kinds, an authenticated webhook sets `transcriptFinal` even if it supplies no nonempty transcript. The workflow treats that marker as ready and may use the browser's transcript (`web/app/api/sessions/webhook/route.ts`, `web/workflows/steps/twin-session-report.ts`, `web/workflows/steps/roleplay-session-report.ts`).
