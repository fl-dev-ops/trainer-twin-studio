# Twins

> A twin is the trainer's AI: a voice conversation about the learner's real situation, using the trainer's identity and published skills. A main twin brings together that persona's skills; a skill twin covers one topic. This module manages twin settings, access, source links, calibration and studio views of conversations. Calls themselves belong to [Sessions](sessions.md). (`web/lib/twins.ts`, `web/lib/twin/trpc.ts`, `chat/prompts/twin.md`.)

## Who uses it

| Who | What they can do here | Code |
| --- | --- | --- |
| Org admin and team (studio members) | View and configure twins, assign learners, copy links, calibrate, see learner sessions and reports. Direct calls and learner-page previews need no learner assignment; billed staff voice calls use org credits, unbilled staff calls are free. | `web/lib/trpc.ts` `studioProcedure`; `web/lib/twin/trpc.ts`; `web/lib/interview-sessions.ts` `activateSession`; `web/lib/pages/learner.ts` `twinAccessFor` |
| Learner (`user` role) | Talk to assigned twins while access and credits remain. Opening an active legacy common `/s/` link can add an existing account to the org, grant starting credits once and create/reuse its assignment before prejoin. Cannot use the studio twin router. | `web/lib/twin-access.ts` `usable`, `twinAccessByCode`; `web/lib/trpc.ts` |
| Signed-out visitor | See the public trainer/twin profile at a valid `/t/` path; sign in with Google there or follow the email-code link. Seeing or signing into this page grants no access. | `web/lib/pages/learner.ts` `loadTwinLink`; `web/components/twin/twin-learner-flow.tsx` |
| Studio copilot | Publish/revise skill twins; read current/older skill files; change settings; invite learners; archive/restore skills. Its archive action refuses the main twin. | `web/lib/scenario-ingest.ts` `ingestTwinSkill`; `web/lib/copilot-studio.ts` `runCopilotStudio` |
| Chat/voice runtime | Receives session-pinned agent/persona/skills, runs the conversation, records turn evidence and returns call results. | `web/lib/session-context.ts`; `web/app/api/copilot/studio/route.ts`; see [Voice agent and chat](voice-agent-and-chat.md) |

Agreed access/call rules are in [Practice](practice.md); account/member rules are in [People](people.md). This spec describes the implementation, including the gaps below. Roles and enabled membership are owned by [Orgs and roles](orgs-and-roles.md). There is no separate TrainerTwin-staff exception in `studioProcedure` (`web/lib/trpc.ts`).

## Words used here

| Term | Meaning |
| --- | --- |
| Twin | An `Agent` with immutable `kind = TWIN`, linked to an org's own persona (`Persona.isOwn = true`). An invented/global persona is not allowed. (`web/prisma/migrations/20261027000000_split_twin_roleplay/migration.sql`.) |
| Main / all-skills twin | A twin with `Agent.data.source = "twin"`. At call start it gathers skill twins of the same org **and persona**, not every skill in the org. (`web/lib/twins.ts` `pinTwinSkills`; `web/lib/twin-access.ts` `isAllSkillsTwin`.) |
| Skill twin / playbook | One topic's published `SKILL.md` and manifest, stored on another TWIN agent. New skills have source `twin-creator`; older skills have `scenario-ingest`. A main twin uses these as playbooks. (`web/lib/scenario-ingest.ts` `buildTwinSkill`; `web/lib/twins.ts` `toPlaybook`.) |
| Persona | The trainer identity, speaking style, voice and avatar. Shared with other twins; not copied into each skill. See [Personas and voice](personas-and-voice.md). (`web/lib/twin/avatar.ts`.) |
| Version / pin | The numbered agent content. A call snapshots its agent/persona; a main-twin call also stores `{slug, version}` for each skill in `compiledSnapshot.twinSkills`. (`web/lib/interview-sessions.ts` `activateSession`; `web/lib/session-context.ts`.) |
| Assignment | One member account's access to one twin (`TwinAssignment`), active or revoked, with an optional last start time (`accessUntil`). It is not a credit balance. (`web/lib/twin-access.ts`.) |
| Common share link | A legacy `TwinShareLink` code at `/s/<code>`; joining creates/reuses personal access. Not the readable link copied by today's Share action. (`web/lib/twin-access.ts` `twinAccessByCode`; `web/lib/twin/trpc.ts` `agents.shareLink`.) |
| Calibration | A studio member testing a twin by talking to it and rating its replies. Saved as a normal call plus `TwinCalibration` and rating records, not as a learner session. (`web/lib/twin/trpc.ts` `calibrations`; `web/components/calibration/calibration-call.tsx`.) |
| Built from | Version-specific knowledge-document references counted from published example items, not a live connection that rebuilds a skill when a document changes. (`web/lib/skill-sources.ts`.) |
| Credits / minutes | A learner's org-wide prepaid practice time, shared across twins and role plays. See [Credits](credits.md). (`web/lib/twin-access.ts` `listTwinAssignments`.) |

| `InterviewSession` (owned by Sessions) | Twin boundary fields: `twinAssignmentId`, pinned versions/JSON, transcript, recording/evidence, feedback, `report`, `reportStatus`, `reportWorkflowRunId`. Lifecycles:

- Twin: live → archived → restored. Archive keeps the row, versions, artifacts and session history; publishing onto an archived skill also restores it. (`web/lib/specs.ts` `deleteSpec`; `web/lib/copilot-studio.ts` archive/restore; `web/lib/scenario-ingest.ts` `storeSkillAgent`.)
- Assignment: absent → active; active ↔ revoked. Expired means active **but** `accessUntil <= now`, not a stored status. (`web/lib/twin-access.ts` `assignTwin`, `updateTwinAssignment`, `withinAccess`.)
- Common link: active ↔ disabled. Disabling does not revoke assignments already made. (`web/lib/twin-access.ts` `setTwinShareLinkStatus`.)
- Calibration: call and calibration created together → replies rated while live → call ended → scoring claimed → counts and `scoredAt` saved. Model/save failure clears the claim and throws for workflow retry; an unscored claim becomes available again after two minutes. Successful scoring retains the claim timestamp; `scoredAt` prevents another claim. There is no published/approved state. (`web/lib/interview-sessions.ts:398–403`; `web/lib/twin/trpc.ts:579–592`; `web/lib/twin/calibration-score.ts:71–103`; `web/workflows/steps/calibration.ts:18–22`.)

## How it works

### Create, edit and archive

1. `POST /api/twins` takes `personaSlug`. `ensureTwin` finds that org's own persona case-insensitively and builds `<org slug>-<persona slug>-twin`. Missing org/persona is 404; invalid resulting slug is 400; another org owning that slug is 409. An existing same-org slug returns `created: false` (200), otherwise it creates a version-1 TWIN agent (201). This function creates no Domain row. (`web/app/api/twins/route.ts`; `web/lib/twins.ts` `ensureTwin`.)
2. The library's **Create new** requests a *skill*, not a main twin. Without an own persona, it asks for persona setup. Otherwise a non-empty topic (UI maximum 1,000 characters) seeds the copilot with `twin-creator`, the persona and the topic, then opens studio `/`. The request is not itself publication. (`web/components/twin/twin-agents-page.tsx` `CreateSkillDialog`; see [Copilot](copilot.md).)
3. Copilot publication calls `POST /api/internal/twin-skills` with a bearer ingest secret and org header. The body includes SKILL.md, skill.json manifest, trainer-only items and optional evidence/change files. Invalid input is 400, missing own persona is 404, org/kind collisions are 409; unexpected storage errors return 500. Older scenario packages remain supported at `/api/internal/scenarios`. (`web/app/api/internal/twin-skills/route.ts`; `web/lib/scenario-ingest.ts` `twinSkillIngestSchema`, `ingestTwinSkill`, `ingestScenario`.)
4. Configure edits name/description and before/during permissions. General saves with **Save changes**; switches save immediately through a serialized queue; upload title/instruction save together with their own Save. Failed writes show a toast; switch state returns to the saved settings. `updateTwin` keeps unspecified content, snapshots old JSON and increments the version on change. (`web/components/twin/twin-edit-page.tsx`; `web/lib/twin/manage.ts`.)
5. Copilot can archive/restore a skill; it explicitly refuses main-twin archive. Generic `DELETE /api/spec/agents/<slug>` instead archives any org-owned agent, including a main twin. The skill-card **Remove** menu currently has no handler. Archive removes twins from normal lists, path resolution, new-call snapshots and live skill selection, not past session lists. See Open questions for the unequal archive controls. (`web/lib/copilot-studio.ts` archive/restore; `web/app/api/spec/[type]/[[...id]]/route.ts`; `web/lib/specs.ts` `deleteSpec`; `web/components/twin/twin-agents-page.tsx`; `web/lib/twin-access.ts` `resolveTwinPath`; `web/lib/interview-sessions.ts` `sessionSnapshot`; `web/lib/twins.ts` `liveSkillTwins`; `web/lib/twin/trpc.ts` `learnerSessions`.)

### Publish skills and keep a session's versions

1. New skill slugs are `<org slug>-<manifest.skill>`. The manifest names 1–30 situations; new items must contain only the trainer's words. `buildTwinSkill` puts situations in stages and keeps the manifest under `data.scenario`. Older scenario-shaped playbooks with steps/moves remain readable. (`web/lib/scenario-ingest.ts` `twinSkillManifestSchema`, `twinSkillIngestSchema`, `buildTwinSkill`; `web/lib/twins.ts` `toPlaybook`.)
2. `storeSkillAgent` compares stable content, persona and a hash of items/patterns. Unchanged content keeps its version. Changed content advances the version and snapshots old JSON. It preserves existing `introVideo`, `before`, `twinSettings`, `after` and `tools`. (`web/lib/scenario-ingest.ts` `KEPT_ACROSS_DURING_WRITES`, `storeSkillAgent`.)
3. Files go to the S3 version folder first, version-tagged example items to Chroma second, and live agent/source rows to PostgreSQL last. A failure before the switch leaves the live row on its previous version, although unused artifacts/items may remain. Source rows count `metadata.source` only when it identifies this org's knowledge document. (`web/lib/scenario-ingest.ts` `storeSkillAgent`; `web/lib/s3.ts` `scenarioArtifactsPrefix`; `web/lib/skill-sources.ts` `skillSourceRows`.)
4. Starting a main-twin call pins every live, parseable skill of the same persona as `{slug, version}`. Later skills are not added to that call. `buildSessionContext` loads matching live data or the old `SpecVersion` JSON. Older sessions with no skill pin use the current list. A new-format single-skill twin uses its own snapshotted skill as its sole playbook; older scenario-shaped single skills use the older scenario flow. (`web/lib/interview-sessions.ts` `activateSession`; `web/lib/twins.ts` `pinTwinSkills`, `twinPlaybooks`; `web/lib/session-context.ts` `buildSessionContext`; `chat/agent/lib/brain.ts` `twinSessionPlaybooks`, `scenarioPlaybook`.)
5. Example lookup also passes pinned versions: the main twin searches the pinned playbooks; a single skill uses the session's `agentVersion`. Unknown playbook names widen to all the main twin's playbooks, not unrelated personas. Chroma retains the published version and its predecessor; if no hits exist at the requested versions, lookup falls back to retained versions of those same slugs. This is not strict forever-pinning of example lines. (`web/app/api/copilot/studio/route.ts` `searchScenarioItems`; `web/lib/main-collection.ts` `writeScenarioItems`, `pruneScenarioItems`, `searchScenarioItems`.)

### Give access and share a link

1. Configure/Assign opens the shared learner picker. It accepts existing learners or new emails, optional access end day, and starting credits for new people. The end day becomes 23:59:59.999 in the assigning browser's time zone, sent as an ISO instant. (`web/components/twin/twin-edit-page.tsx`; `web/components/assign-dialog.tsx`.)
2. `assignments.assign` calls `runTwinAssign`: its assign-twin workflow calls `assignTwinLearners`. `addPeopleToOrg` takes `minutes:<org>` then `people:<org>`; starting grants, accounts, members and userId assignments commit together. Its `then(tx, people)` hook calls `assignTwin` inside that transaction. A failed assignment rolls back the entire batch. After commit, it queues one combined person email for new/reactivated access (added/twin/credits when new). Credit shortage fails before assignment/mail. Existing credit holders keep their credits. Queued emails expose an org-signed progress token; inline startup fallback reports emailFailures; successful assignments are not rolled back. See [Invites and emails](invites-and-emails.md) and [Credits](credits.md). (`web/lib/twin/trpc.ts` `assignments.assign`; `web/lib/invite/twin.ts`; `web/components/twin/twin-edit-page.tsx` `assignLearners`.)
3. `addPeopleToOrg` normalizes/deduplicates emails and refuses disabled/studio recipients; `assignTwin` receives those members. An active assignment is skipped, **even if its end date has passed**. A revoked one is reactivated with the new date and a new personal code. REST PATCH can revoke/restore under `people:<org>`, but does not edit its end date or rotate its code. Restore reads the person again in that transaction: missing member is `not_found`/404; disabled is `person_disabled`/409; admin/team is `person_is_studio`/409. Configure lists assigned people without remove/revoke controls. (`web/lib/twin-access.ts` `assignTwin`, `updateTwinAssignment`; `web/app/api/twins/[slug]/assignments/route.ts`; `web/components/twin/twin-edit-page.tsx`.)
4. Today's Share action returns a readable URL only; it creates no `TwinShareLink` or assignment. Main URL: `/t/<own-persona slug>`. Skill URL: `/t/<agent slug without org prefix>`, except a short name matching any own-persona username shares the full agent slug. (`web/lib/twin/trpc.ts` `agents.shareLink`; `web/lib/twin-access.ts` `twinSharePath`; `web/components/twin/share-twin-dialog.tsx`.)
5. `/t/<path>` resolves in the host's org: trim/lowercase → own-persona slug and its non-archived main twin → org-prefixed short agent slug → full agent slug. Only TWIN/non-archived agents qualify. If a username has no main twin, resolution continues to the agent-slug fallbacks. Resolution does not need an active common link. (`web/lib/twin-access.ts` `resolveTwinPath`; `web/lib/pages/learner.ts` `loadTwinLink`.)
6. For a learner, readable-link access resolves **their existing assignment** and uses its personal code. It checks ownership, active status and future/null `accessUntil`; the required userId must match the signed-in account, never its email. Studio members instead get a preview and start directly by slug, without a learner assignment; billed voice calls debit org credits, not learner credits. (`web/lib/pages/learner.ts` `twinAccessFor`; `web/lib/twin-access.ts` `twinAssignmentCode`, `usable`; `web/components/twin/twin-learner-flow.tsx`; `web/components/calibration/calibration-call.tsx` `start`.)
7. Legacy `/s/<code>` still recognizes a personal assignment or common link. Page load checks with `join: true`: an active common link reuses the account's assignment or calls addPeopleToOrg to add the learner/grant starting credits once, then creates an assignment by userId before prejoin. Personal codes check existing ownership even for admin/team; only common codes let studio bypass assignment. The common-link assignment is inserted with `createMany(skipDuplicates)` inside `addPeopleToOrg`'s `then` hook; grants, member and assignment commit together, and the unique `(agentId,userId)` keeps one access row for concurrent tabs. No email is sent. Session start uses a fresh twin key, never resumes, and checks with `join: false`, never adding members or assignments: a member without access gets `twin_not_assigned`/403, a nonmember gets `no_org`/403. Unknown codes return null; another org's code and an archived twin throw `not_found`/404 before ownership/link checks. Revoked/expired existing access is refused, not reset by reopening the link. A disabled common code is refused even for a previous joiner, but their personal code and readable URL still work while their assignment is usable. (`web/lib/pages/learner.ts` `loadSharedSession`; `web/lib/twin-access.ts` `findTwinCode`, `twinAccessByCode`; `web/lib/interview-sessions.ts` `activateSession`.)
8. Pages and Start share `practicePerson` (enabled membership) and `startAllowance` (pause, five-minute learner/org minimum, free unbilled studio), with access/live-twin checks separately in twin access (assertLiveTwin). Start takes `minutes:<org>`, rechecks the person, ends/charges every other live call by this person in this org, checks the resulting allowance and creates the new call in one transaction. A refusal rolls back those ends. Studio calls now use the same replacement/end path; billed live studio calls reserve their whole allowance. Access/live-twin checks are still outside that transaction; see Mismatches. `accessUntil` only gates starting, not a running call. Activation, deadlines and finalization belong to [Sessions](sessions.md). (`web/lib/practice.ts` `practicePerson`, `startAllowance`; `web/lib/interview-sessions.ts:352–404` `activateSession`; `web/lib/org-credits.ts` `runningSeconds`.)

Access refusals currently thrown by the service (AppError; REST returns `{error,code}`, tRPC keeps `data.refusal`):

| Condition | Code / status / message | Code |
| --- | --- | --- |
| Missing learner assignment or another account's personal code | `twin_not_assigned` / 403 / This twin isn't assigned to you. Ask your trainer for access. | `web/lib/twin-access.ts:22,111–112` `twinRefusals`, `usable` |

Personal codes now check org membership/disabled state before usable assignment: no_org/403 for a nonmember, member_disabled/403 for disabled. Studio ownership is still checked on personal codes, as Practice 2 specifies (`web/lib/twin-access.ts:149–153`).

### What a learner without access sees

- A valid `/t/` page still shows the trainer's name, role/place, bio/photo, twin name and description. Signed out, **Start conversation** opens a Google dialog with an email-code link; either returns there. Unknown/archived paths show **Twin not found**. (`web/lib/pages/learner.ts` `trainerProfile`, `twinProfile`, `loadTwinLink`; `web/app/(org)/t/[slug]/page.tsx`; `web/components/twin/twin-learner-flow.tsx`.)
- Signed in as org member without assignment: **This twin isn't yours yet**. Outside org: **You're not in this organization yet**, asking for addition or switching to the added account. Revoked or elapsed access: **Your access has ended**. With access but less than 60 seconds left: **You've used all your minutes**. A short balance (60–299 seconds), pause, disabled membership or studio credit refusal becomes `reason: "blocked"`, with **You can't start a call right now** and the service's message. All these results have `ok: false`, a saved message and no start-call dock; the four older reason variants still replace that message with their own copy. Studio previews can be blocked too. (`web/lib/pages/learner.ts:190–219` `ACCESS_REASONS`, `twinAccessFor`; `web/components/twin/twin-learner-flow.tsx:55–60` `noAccessCopy`.)
- Org home publicly lists main twins and their skill topics with access state; this is not the same as the talk-page startable catalog, which filters out unassigned/expired twins. See [Learner portal](learner-portal.md). (`web/lib/pages/org-home.ts` `loadOrgHome`; `web/lib/twin-access.ts` `startableAgentSlugs`.)
- A rejected personal/common `/s/` twin code shows the access error; unauthenticated `/s/` visitors go to sign-in with a return URL. It does not use the public `/t/` profile flow. (`web/lib/pages/learner.ts` `loadSharedSession`; `web/app/(org)/s/[code]/page.tsx`.)

### Calibrate and save results

1. Calibration pages and procedures are studio-only. The live page loads face/settings, then shows `CalibrationCall` with `twin` and no learner mode. Start posts a voice call by slug with `calibrate: true`. The service refuses a learner with `studio_only` before twin access lookup; a studio calibration on a non-twin is `not_found`. Under `minutes:<org>`, it creates the call and `TwinCalibration(createdByUserId = userId)` in the same transaction, after the normal studio allowance/replacement checks. Insertion failure rolls both back. The response carries `session.calibrationId`; chat initializes only after commit. No separate `calibrations.start` or `calibrations.score` mutation remains. Prejoin does not check practice allowance; see Mismatches. (`web/app/dash/twin/[id]/calibrate/page.tsx:9–13`; `web/components/calibration/calibration-call.tsx:279–305`; `web/lib/interview-sessions.ts:232–236,311–315,358–439`; see [Sessions](sessions.md).)
2. Ratings become available with that returned ID. The UI offers only the latest finished, not-yet-rated reply. **Feels like me** saves `like`; **Feels off** saves `off` and sends “Feels off” into the call. The creator's live-call check happens on every server rating request; another creator/org, a deleted call or archived twin gives `not_found`/404/“Not found.” A found call outside activating/active gives `calibration_ended`/409/“This calibration call has ended.” Feedback affects the rest of this call, not published skills or future calls (see [Voice agent and chat](voice-agent-and-chat.md)). (`web/components/calibration/calibration-call.tsx:424–441,545–546,665–685`; `web/lib/twin/trpc.ts:514,579–592`.)
3. Writes store the local turn index, latest preceding trainer question and trimmed reply as rated. Re-rating through the API replaces the same key. The browser retries rating writes up to three attempts; final failure shows “That rating was not saved.” End/unmount waits for the current pending promises, finalizes and disconnects; this cannot guarantee a killed tab finishes saving. Finalize retries network/5xx failures up to three attempts (one keepalive attempt on unmount); even on save failure, it warns and leaves. Manual studio End finalizes as abandoned; a completed agent/workspace event finalizes as completed. (`web/components/calibration/calibration-call.tsx:51–59,183–235,348–359,403–412,426–441,823`; see [Sessions](sessions.md).)
4. Normal end navigates to the saved review without scoring in the browser. Org studio members may read any visible calibration. `get` and `rate` share `orgCalibration`: org, undeleted call and unarchived twin. List first resolves a live twin, then reads at most 100 newest calibrations by creation time, excluding deleted calls. Review matches ratings to the transcript by normalized reply text, then containment; unmatched ratings/questions are appended. A fresh call resets ID, pending writes and turn counter. Review/history use ordinary `useApi` refetches, not a scoring poll. 5. The end-twin-session workflow closes the room, charges idempotently, then detects calibration before claiming an ordinary report. The winner reads transcript and ratings, calls Jev's `decide` once when there are questions, and saves counts/`scoredAt`. No questions saves raw counts/`scoredAt` without Jev. 6. ## Rules

1. An agent must declare its kind; TWIN kind and persona `isOwn` cannot be changed after creation. A TWIN must use a same-org own persona, never a global/invented one. (`web/prisma/migrations/20261027000000_split_twin_roleplay/migration.sql`.)
2. All twin-router procedures require an enabled org membership with admin/team role. All twin pages are behind `requireStudioMember`. Learners/anonymous callers cannot rate or read calibrations through this router. (`web/lib/trpc.ts` `protectedProcedure`, `studioProcedure`; `web/app/dash/twin/layout.tsx`; `web/lib/twin/trpc.ts`.)
3. Studio management lookup refuses another org's, ROLEPLAY or archived agent with 404. (`web/lib/twin-access.ts` `findTwinAgent`.)
4. Update accepts trimmed name of 1–120 characters, description up to 2,000, three boolean permissions, upload title up to 80 and instruction up to 300. Same JSON/name is a version no-op; real change snapshots and increments in one transaction. (`web/lib/twin/trpc.ts` `agents.update`; `web/lib/twin/manage.ts` `updateTwin`.)
5. `before` overrides older `twinSettings`. All three permission switches default false. Twin uploads are optional, max one before the call; instruction text never makes them required. Start-time documents and mid-call attachments are checked server-side against the call's settings; session attachment enforcement belongs to [Sessions](sessions.md). (`web/lib/context-upload.ts` `beforeSettings`, `contextUploadFromAgentData`; `web/lib/interview-sessions.ts` `activateSession`; `web/app/api/sessions/[id]/documents/route.ts`.)
6. Assignment requests take 1–100 normalized valid emails (each at most 320 characters). Optional `accessUntil` must be null or strictly in the future; `startingMinutes`, when present, is an integer 1–360 for new credit holders only. REST's optional legacy `minutes` validates 1–10,000 but is ignored. (`web/lib/twin/trpc.ts` `assignments.assign`; `web/lib/twin-access.ts` `accessUntilSchema`; `web/lib/minutes.ts` `MAX_LEARNER_MINUTES`; `web/app/api/twins/[slug]/assignments/route.ts`.)
7. One assignment per `(agentId,userId)`; userId is required and must belong to a member of orgId. Assignment/link must point to a TWIN in the same org; a link-made assignment must refer to that link's twin. Legacy minute columns must still be positive at the DB boundary. (`web/prisma/schema.prisma`; `web/prisma/migrations/20261027020000_twin_access/migration.sql`.)
8. Personal-code ownership uses required userId only. Inactive or expired access is 403. Exactly at `accessUntil` is expired; a running call is not ended by that date. (`web/lib/twin-access.ts` `usable`, `withinAccess`.)
9. Reading/sharing `/t/` creates no assignment or starting credits. Opening an active legacy common-code page with an existing signed-in account can add a learner and create access through addPeopleToOrg; session start cannot. Reopening never resets revoked/expired access or tops up an existing credit holder. (`web/lib/twin/trpc.ts` `agents.shareLink`; `web/lib/pages/learner.ts` `loadTwinLink`; `web/lib/twin-access.ts` `twinAccessByCode`; `web/lib/minutes.ts` `giveStartingMinutes`.)
10. Twin sessions are voice-only. Without a twin assignment, DB permits only admin/team membership. A session cannot carry both role-play and twin assignment IDs; the twin assignment must belong to the session's user/org/twin. (`web/prisma/migrations/20261027020000_twin_access/migration.sql`; `web/lib/interview-sessions.ts` `activateSession`.)
11. `calibrate: true` creates one calibration with its new twin call; twin starts never resume or reuse a caller idempotency key. Only its creator may rate while activating/active; all org studio members may read visible calibrations. Rating index is integer 0–10,000, reply trimmed non-empty up to 8,000 characters, question trimmed nullable/up to 8,000, rating like/off. Input failures give tRPC BAD_REQUEST/400 with `data.refusal = invalid_input`. Lists take at most 100 newest. (`web/lib/interview-sessions.ts:236,308–314,398–403`; `web/lib/twin/trpc.ts:139,514–594`; `web/lib/trpc.ts:54–58`.)
12. Calibration DB accepts only TWIN sessions, one calibration per session, nonnegative turn indexes, one rating per turn, and like/off values. (`web/prisma/migrations/20261027030000_twin_calibration/migration.sql`.)
13. Most-asked/declined grouping trims, lowercases and collapses whitespace; each question counts at most once per session. Highest counts first; ties keep first encountered order; return top three. (`web/lib/twin/stats.ts` `mostAsked`.)
14. The new twin conversation prompt tells the model to advise from playbooks, speak in first person, avoid inventing trainer facts and decline uncovered advice with “I can't answer this question, please ask the real <first name>.” This is a prompt contract, not a deterministic guarantee about generated speech. No agenda/quota/grading or `session_plan`; rehearsal is allowed only when the learner asks. (`chat/prompts/twin.md`; `chat/agent/lib/brain.ts` `twinDeclineLine`, `formatTwinSession`; see [Voice agent and chat](voice-agent-and-chat.md).)

## Edge cases and limits

- Main creation is slug-idempotent, not a unique `(persona, main source)` upsert. Any existing same-org slug is returned without checking kind/source/persona, and an archived existing main is not restored by `ensureTwin`. (`web/lib/twins.ts` `ensureTwin`.)
- Active-but-expired assignments remain marked assigned in studio lists/counts; only learner/startable checks compare `accessUntil`. Reassigning such an active row skips it. (`web/lib/twin/trpc.ts` `agents.list`, `assignments.list`, `users.list`; `web/lib/twin-access.ts` `assignTwin`, `usable`.)
- A disabled common link stops use of that code, not use of existing personal access. Link joins have no access-until field; new link-created assignments have no end date. (`web/lib/twin-access.ts` `twinAccessByCode`.)
- Common-link grants/membership/assignment creation happens on page opening, before its balance check and any call. Leaving prejoin or later activation failure does not undo it; page loading and voice activation are separate actions. (`web/lib/pages/learner.ts` `loadSharedSession`; `web/lib/interview-sessions.ts` `activateSession`; `web/lib/twin-access.ts` `twinAccessByCode`.)
- Source links count examples, not the percentage of a skill's factual grounding. Sources not matching this org's documents get no rows; deleted document references keep saved title/count and no live link. (`web/lib/skill-sources.ts` `skillSourceRows`, `builtFrom`; `web/components/twin/twin-agent-detail-page.tsx`.)
- Version lookup is not an absolute freeze: older sessions without pins use live skills; missing historical JSON yields no playbook; retained `SpecVersion` can supply an archived/missing live skill; pruned example versions fall back to retained examples. (`web/lib/twins.ts` `twinPlaybooks`; `web/lib/main-collection.ts` `searchScenarioItems`.)
- `shortcut:` learner activity counts and twin detail statistics use the latest 200 sessions, not lifetime grouped queries. Most-asked is exact normalized text, not semantic grouping. (`web/lib/twin/trpc.ts` `learnerActivity`, `agents.get`; `web/lib/twin/stats.ts` `mostAsked`.)
- Brain coaching principles are a fixed list (Olga's) and “Last updated 2 days ago” is literal copy. Neither proves current training state. (`web/components/twin/twin-brain-page.tsx`.)
- `shortcut:` Jev's shared calibration context keeps only the last 24,000 characters of long calls, although individual questions still cover all turns. Until successful scoring, raw counts are computed on reads; no-question scoring saves them. Scores do not regenerate for a later final transcript. Normal concurrent scoring is claimed, but a two-minute takeover or model-success/save-failure retry is not an exactly-once external-model guarantee. A recently claimed row is skipped and the workflow still returns `calibration: "scored"`. (`web/lib/twin/calibration-score.ts:29–43,58–62,80–103`; `web/workflows/steps/calibration.ts:18–22`; `web/workflows/end-twin-session.ts:25–26`.)
- Turn evidence drops tool calls when its serialized data exceeds 60,000 characters, retaining heard/reply plus `truncated`. Orphan pending example-line records are hidden from the review. (`web/lib/twin/evidence.ts` `recordTurnEvidence`, `sessionEvidence`.)
- `/t/` refuses below five minutes in its loader, not only in a disabled button: below one minute is `used`, 1–4 is `blocked` with `credits_short`. Home uses the same result. Pages use cached studio credits; Start refreshes them before taking the lock. (`web/lib/pages/learner.ts` `twinAccessFor`; `web/lib/pages/org-home.ts` `loadOrgHome`; `web/lib/practice.ts` `startAllowance`; `web/lib/interview-sessions.ts:349–361`.)

## Open questions

1. Should main-twin detail show **only its persona's skills and Built from sources**? Runtime `pinTwinSkills` filters by persona; `agents.get` currently fetches all non-main live twins in the org for its skills/source display. (`web/lib/twins.ts`; `web/lib/twin/trpc.ts` `agents.get`.)
2. May a main twin be archived? Copilot rejects it, generic spec DELETE allows it, and the skill-card Remove button does nothing. Which surface should tests treat as the intended user action? (`web/lib/copilot-studio.ts` archive; `web/lib/specs.ts` `deleteSpec`; `web/components/twin/twin-agents-page.tsx`.)
3. Must an archived skill disappear from an already pinned call? `twinPlaybooks` says deleted skills are dropped and queries only live rows, but can still restore their saved `SpecVersion` data even without a live row. Existing tests cover a missing skill **without** a retained snapshot, not that case. (`web/lib/twins.ts` `twinPlaybooks`; `web/tests/lib/twin-playbooks.test.ts`.)
4. How should active-but-expired access be extended? Assignment APIs skip active rows; PATCH changes only status. Currently revoke then reassign can set a new date, but Configure has no revoke/date-edit control for existing assignments. (`web/lib/twin-access.ts` `assignTwin`, `updateTwinAssignment`; `web/components/twin/twin-edit-page.tsx`.)
5. Should common-link joining require a button? See [Practice's open question](practice.md#open-questions): page/query loading currently commits the join, not pressing Start. (`web/lib/pages/learner.ts:102`; `web/lib/twin-access.ts:167–178`.)
